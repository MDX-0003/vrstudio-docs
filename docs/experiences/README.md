# 经验文档索引

本目录按话题存放可复用的操作经验：一套流程怎么做、配置写在哪、踩过哪些坑。与 `docs/plan/` 的区别是，这里记录的是「已经跑通过的做法」，不承载待批方案；与 `docs/test-runs/` 的区别是，这里不写单次验收的逐条证据，只沉淀下次还会用到的东西。

## 命名与结构

- 文件名用「领域-主题.md」，全小写、连字符分隔，例如 `dsh-browser-frontend-verification.md`。
- 每篇开头写记录日期与适用场景；正文按「部件构成 → 前置检查 → 配置 → 操作流程 → 踩坑 → 证据 → 回滚 → 边界」组织，可按话题裁剪。
- 踩坑条目一条一个现象，写清「现象、原因、处理」，不写「注意一下」这类没有判据的话。
- 引用其他文档用相对路径。
