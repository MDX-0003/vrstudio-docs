## 3 · 提示词编辑界面（已实现，决策 18；2026-10-16 第二轮动工）

> 最后我认为前端手动输入提示词是难以忍受的，网页上首先需要完整显示提示词模板的
> 每一段内容，包括key 和 value，如果有不能修改的就显示，能修改的就让value显示在某个
> 输入框里。另外我认为网页上修改的提示词模块应该支持增删改查，当然模板里已有的字段
> 不应该被删除，但用户应当有办法添加和删除自定义key-val对。我还需要允许网页上修改的
> 提示词能够实时保存到case文件夹下，保证下次打开case，上次写的自定义提示词还在。

拆解出的功能点：

1. 完整展示模板：模板的每一段（key 与 value）都在页面上显示；
   不可修改的段落只读展示，可修改的段落（即 [vars] 里的变量）用输入框承载 value。
2. 增删改查：模板自带的字段不可删除；用户可以添加自定义 key-value，也可以删除
   自己加过的。
3. 实时保存：网页上改的内容立即保存，重新打开 case 后自定义内容还在。

现状与设计要点（实现前需要拍板的）：

- 模板本体在 vrgen 仓库（templates/360-closure.md，markdown + 占位符）；
  变量草稿是 vrgen 侧的 `runs/<job>/prompt-vars.toml`（template + [vars]，
  已有真实样例：theme / style 两段）。
- 跨仓库硬规则（AGENTS.md 第 1 条）：vrstudio 的 web 不得 import vrgen，只能走 CLI。
  所以"展示模板骨架（哪些段只读、哪些段是变量）"需要在 vrgen 增加一个只读 CLI
  命令（如 `vrgen prompt show --job`，输出模板逐段内容 + 变量名集合），保存则复用
  现有草稿机制（新增 `vrgen prompt save --job --set k=v` 或等价命令，写入
  prompt-vars.toml）。
- 用户要求"保存到 case 文件夹下"，而现有草稿在 runs/<job>/ 下。两个方案：
  - A：草稿仍归 vrgen（runs/<job>/prompt-vars.toml，单一权威），web 每次
    修改即调 vrgen 保存；case 打开时 web 经 CLI 读回。符合"生成侧知识住 vrgen"
    的既有决策（决策 7/8）。
  - B：case 目录存一份副本（cases/<name>/prompt-vars.toml），submit 时由
    generate 透传。会存在两份草稿漂移的问题。
  - 倾向 A；最终由实现前的问答确认。
- 变量的增删即 prompt-vars.toml [vars] 段的增删——vrgen 的 --set 键集合自适应
  （决策 9）已经支持新增字段零代码，删除需要一个显式的 CLI 动作。
- 页面落点：generate 步骤内新增"提示词"分区，或独立一步；倾向前者（生成的一部分）。
- 防呆：模板占位符与变量一一对应校验、"还没选模板"时的空态、并发编辑
  （多标签页）以最后写入为准并在页面上提示。

落地情况（2026-10-16）：

- vrgen 新增 `prompt show / save`（JSON 契约见 case-model.md §4）；`--set` 允许新键、
  `--unset` 拒删模板正文引用的键、模板必须存在，全部退出码 2 fail loud。
- 存储按方案 A：草稿权威在 `runs/<job>/prompt-vars.toml`（job = case 名），
  web 经 `POST /api/case/<n>/prompt` 调 vrgen 保存；"下次打开还在"经 CLI 读回达成，
  case 目录不新增提示词文件（守住决策 7）。
- 生成页新增"提示词"分区：模板正文只读展示（花括号占位原样可见）、模板自带变量
  （theme/style）只能改值、自定义变量可增删、改动即时保存（输入框失焦即写）。
  submit 不再走页面上的临时 k=v 输入（已移除），变量一律以保存的草稿为准。
- 任务队列（同轮）：每个任务行首带提交时间（MM-DD HH:MM:SS），历史窗口 3→10 条，
  渲染分「正在执行 / 排队等候（早提交的先跑）/ 最近完成（新→旧）」三节。
- 防呆一项未做：并发编辑（多标签页）提示——单人本地工具暂不设防，多用户轮次再补。

## 第三轮反馈（2026-10-16，对比页）

> 在网页上观看修改前后视频这很好，但是有两个问题：1.这是360视频，要么能够在网页
> 自由旋转视角，要么就把360视频展平再观看，我希望是前者。2.视频下面的进度条和
> 播放/暂停按钮只在"原始视频"那一侧显示，并且该ui只对原始视频生效，但是点击下去
> 又会导致结果视频也暂停。我希望的效果是有一个统一的进度条+按钮，能够控制两份视频的启停

拆解与落地：

- **360° 全景观看（取用户要的"自由旋转"）**：新增 `erp360.js`——WebGL 手写
  ERP 投影着色器，无第三方库（决策 11 原生栈）。一块画布同画两路视频：整幅先画
  原片，分割线右侧用 scissor 重画成片；两路共用同一组视角 uniform，转头/变焦
  永远同步——逐列检查接缝时两边看的是同一个方向。按住拖动转头（内容跟手），
  滚轮变焦（水平 fov 30°–120°，页面不跟滚），「回正视角」一键复位。
- **统一传输控制**：原片的原生 controls 移除——它就是"只在左侧显示、点了却连
  成片一起停"的原因。换成一进度条 + 一播放按钮，同时驱动两份视频；成片仍以原片
  为时钟主，进度偏差超过 0.05 秒自动对齐（沿既有事件同步机制）。
- **分割线语义收窄**：只改左右占比（2%–98%），与视角拖动彻底分离——竖条上的
  按下事件 stopPropagation，画布其余区域才是转头。
- 实现注意：纹理以「currentSrc + currentTime」为脏标记，暂停时不重复喂 GPU；
  换成片文件时 src 未变则不重挂（避免回跳 0:00）。视频元素隐藏保留（WebGL 纹理源）。
- 浏览器验收：拖动 160px = yaw 0.314 rad（与 90° fov 换算精确一致）且两侧同步；
  分割线拖至 25% 生效；统一进度条 seek 后两路 currentTime 相等；播放到结尾两路
  同停、按钮图标回 ▶；滚轮 90°→70.8°→上限 120°。

## 第四轮反馈（2026-10-19，生成参数与提示词）

本轮用户确认的要求（对话原文未逐字留档，要点据 `decisions.md` 决策 20 的确认记录）：

- 生成页必须能直接指定必要参数，并看到每个选项对应的具体宽高。
- 输入端缩放只保留 `auto` / `full` / `half` 三档，不把内部调试用的 `quarter` 或显式宽高暴露到页面。
- 提示词要能约束情节与动作，并单独设计“哪些允许变化”；这些内容允许在前端临时编辑。

拆解与落地：

- 参数拆成两个下拉框：输出档位走 mglc `--resolution`（480p/720p/1080p，页面显示 21:9
  标称宽高），输入档位走 vrgen 自有 `--scale`（页面显示当前 case 在三个档位下的实际宽高）。
  模型 37、videoEdit、21:9、时长、数量固定展示，数量锁 1（vrgen 只取第一个结果）。
- vrgen 新增 `params show/save`，参数按 job 存 `runs/<job>/generation.toml`；`submit`
  增加 `--model-id/--mode/--duration/--num/--aspect-ratio/--scale`（70b7a2a）。
- 提示词模板新增【情节与动作】【允许变化】两节，变量为 `plot` / `action` /
  `allowed_changes`；输出画布措辞改为“保持相同 21:9 构图与覆盖范围”，不再声称输出
  像素等于输入文件。
- vrstudio 生成页落地两个下拉框并透传 submit 参数（e85828a）。
- 已知迁移缺口：既有 case 的 `prompt-vars.toml` 没有这三个新变量，页面会显示空输入框；
  用户不填就提交时 `vrgen submit` 会明确报模板缺少变量，不会静默用空值生成。
