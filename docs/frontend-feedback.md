## 3 · 提示词编辑界面（本轮只规划，不动工）

> 最后我认为前端手动输入提示词是难以忍受的，网页上首先需要完整显示提示词模板的
> 每一段内容，包括key 和 value，如果有不能修改的就显示，能修改的就让value显示在某个
> 输入框里。另外我认为网页上修改的提示词模块应该支持增删改查，当然模板里已有的字段
> 不应该被删除，但用户应当有办法添加和删除自定义key-val对。我还需要允许网页上修改的
> 提示词能够实时保存到case文件夹下，保证下次打开case，上次写的自定义提示词还在。

拆解出的功能点：

1. 完整展示模板：模板的每一段（key 与 value）都在页面上显示；
   不可修改的段落只读展示，可修改的段落（即 [vars] 里的变量）用输入框承载 value。
2. 增删改查：模板自带的字段不可删除；用户可以添加自定义 key-value，也可以删除
   自己加过的。
3. 实时保存：网页上改的内容立即保存，重新打开 case 后自定义内容还在。

现状与设计要点（实现前需要拍板的）：

- 模板本体在 vrgen 仓库（templates/360-closure.md，markdown + 占位符）；
  变量草稿是 vrgen 侧的 `runs/<job>/prompt-vars.toml`（template + [vars]，
  已有真实样例：theme / style 两段）。
- 跨仓库硬规则（AGENTS.md 第 1 条）：vrstudio 的 web 不得 import vrgen，只能走 CLI。
  所以"展示模板骨架（哪些段只读、哪些段是变量）"需要在 vrgen 增加一个只读 CLI
  命令（如 `vrgen prompt show --job`，输出模板逐段内容 + 变量名集合），保存则复用
  现有草稿机制（新增 `vrgen prompt save --job --set k=v` 或等价命令，写入
  prompt-vars.toml）。
- 用户要求"保存到 case 文件夹下"，而现有草稿在 runs/<job>/ 下。两个方案：
  - A：草稿仍归 vrgen（runs/<job>/prompt-vars.toml，单一权威），web 每次
    修改即调 vrgen 保存；case 打开时 web 经 CLI 读回。符合"生成侧知识住 vrgen"
    的既有决策（决策 7/8）。
  - B：case 目录存一份副本（cases/<name>/prompt-vars.toml），submit 时由
    generate 透传。会存在两份草稿漂移的问题。
  - 倾向 A；最终由实现前的问答确认。
- 变量的增删即 prompt-vars.toml [vars] 段的增删——vrgen 的 --set 键集合自适应
  （决策 9）已经支持新增字段零代码，删除需要一个显式的 CLI 动作。
- 页面落点：generate 步骤内新增"提示词"分区，或独立一步；倾向前者（生成的一部分）。
- 防呆：模板占位符与变量一一对应校验、"还没选模板"时的空态、并发编辑
  （多标签页）以最后写入为准并在页面上提示。
