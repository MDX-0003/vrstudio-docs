# 生成页可读性与操作逻辑优化方案

状态：已实施（2026-10-22）。本方案只改生成步骤（`pnl-generate`）的页面结构、
提示词编辑体验与提交入口，不改生成执行链，不改 vrgen submit 行为，
关键帧工作台本轮不动。

实施提交：vrgen `a7079a1`、`f26be9b`；vrstudio `aecd6e9`、`a830f27`；
根仓库 `182f4db`、`78bdb28`。实施中按讨论收敛了三处：

- 「最近成片」只在有未采用可用轮次时显示；已采用且目标文件存在时整行隐藏，
  避免没有动作的状态行。
- 变量卡片只保留显示名、键名与模板里的填写说明；字数与内容片段删除
  （片段只取前 40 字，编辑靠后内容时看起来不更新，反而误导）。
- 只读“自动填入”列表与底部的 `promptMeta` 删除；这些值已经体现在完整提示词里。

## 1. 问题

生成页现在是一条从上到下的长列，七个主题平铺：素材、关键帧、Seedance 入口、
生成参数、扣费额度、提示词、生成记录。实际打开 dacne 页面后确认的问题：

- 提交按钮在最上方，依赖的素材、参数、提示词都在下方；用户无法在点击前核对本次提交。
- 两个概念都叫 Session：扣费用的「生成会话」与底部的「Session 列表」（实际是生成轮次）。
- 「生成记录与选用」把预演轮次、失败轮次、可用成片混在一起。每次改完再预演都会
  留下一条 `stage=prepared` 的轮次，被渲染成「✗ 未生成视频」，是主要的信息污染源。
- 提示词预览固定 `max-height: 220px`、字号 0.72rem，两千多字的提示词只能看到约十行。
- 每个变量是 340px 单行输入框，长文本（如 `plot` 两百多字）无法阅读和编辑。
- 变量显示英文键名 `subject` / `target` / `plot`，非技术用户无法对应到提示词内容。
- 每行重复「模板自带，只能改值」，是噪声。
- 变量在失焦时异步保存，提交请求不等待保存完成，改完立刻提交可能发出旧值。
- 「检查提交命令（不花钱）」是开发者语言；底部 mglc 轮询日志默认常显，是噪声。

## 2. 已确认的决策（2026-10-22 讨论）

1. 占位符的显示名与填写说明直接写进模板语法，不新增映射文件，不维护第二份真源。
2. 生成页按主题分区折叠；变量的每张卡片也可折叠，默认收起。
3. 提交操作常驻视口底部，不随页面滚动消失。
4. 关键帧工作台保持现状。
5. 删除「生成记录与选用」区域。「选用」收敛为「最近成片」一行上的一个按钮，
   仍调用现有 `adopt` op；主页面不再展示全部轮次与过程日志。
6. 生成设置与扣费额度的**控件整体迁入底部提交条**，页面主体不再出现这两个区域；
   底栏是这两项唯一的位置。

## 3. 目标页面层级

原则：提交所需的控件集中在固定底栏，页面主体只保留素材、提示词与结果这类
内容编辑区；折叠的是内容区，不折叠提交控件与主操作。

```
生成步骤主体
│
├─ 最近成片（仅在有可用未采用成片时出现）
│   ✓ 成片已生成 · 10-22 09:54 · Seedance          [选用成片]
│
├─ ▾ 素材与本次提交集              已勾选 2 项 · 1 视频 / 1 图片
│   ├─ [全选] [全不选] [反选]
│   ├─ 素材卡片 × N
│   │   ├─ ☑ 缩略图
│   │   ├─ 名称 · @Video1 · 1920×1080 · 9.8 秒 · 60fps
│   │   ├─ 角色下拉（编辑母版 / 主体参考 / …）
│   │   └─ [↑] [↓] [删除]
│   ├─ [＋ 添加视频或图片]
│   ├─ 本次提交说明（随模式变化的一句）
│   └─ ▸ 不参与提交的流程文件（N 项）
│
├─ ▸ 关键帧工作台（首帧 / 尾帧重绘）        本轮不动
│
├─ ▸ 提示词                    character-repaint · 6 个可编辑变量
│   ├─ ▸ 完整提示词（约 2,140 字）            ← 默认展开
│   │   └─ 自适应预览区：高度随内容增长，65vh 封顶后内部滚动
│   ├─ ▸ 原主体  subject
│   │   ├─ 写画面里要被替换的主体；模型据此判断改哪个对象。
│   │   └─ 多行输入框：3 行起随内容增高，40vh 封顶
│   ├─ ▸ 重绘结果  target
│   ├─ ……（每个可编辑变量一张卡片，默认收起）
│   └─ ▸ ＋ 添加变量
│
├─ ▸ 外部成片（原“用别的工具做好的视频”）
│   └─ [选用外部视频执行后续步骤]
│
└─ 任务（保持现状）

底部提交条（fixed，仅生成步骤显示；生成设置与扣费额度只在这里出现）
├ 第一行：生成设置  模式▾  比例▾  输出分辨率▾  输入分辨率▾  时长▾   [预演检查] [提交生成]
└ 第二行：扣费额度  项目▾  剧集▾  会话▾  [刷新]   素材 2 项 · ✓ 预演通过 · 未改动
```

- 第一行是生成设置的五个控件与两个操作按钮；第二行是扣费额度的三个控件、
  刷新按钮与状态文字。控件沿用现有 id（`genMode`/`genAspect`/`genResolution`/
  `genScale`/`genDuration`/`sessProject`/`sessEpisode`/`sessSession`），
  `params.js` 里的生成参数与会话逻辑不需要重写，只换宿主容器。
- 状态文字按优先级显示：参数读取失败 → 门控缺口 → 预演状态 → 默认的
  `素材 N 项`。门控不满足时两个按钮禁用，状态文字给具体原因。会话保存状态
  单独显示在会话下拉框旁边，不参与这条优先级链。
- 模型与数量的固定信息（`genFixed`）收进「生成设置」标签的 `title`；
  扣费额度的说明文字收进「扣费额度」标签的 `title`，不再占页面正文。
- 项目名、剧集名、会话名过长时下拉框截断显示，`title` 给全名；失效会话用红色。
- 窄屏时两行允许换行，底栏高度随内容增长，不做内部滚动；页面底部留白随底栏
  高度动态调整。
- 默认展开状态：素材展开，其余全部收起。提示词区展开后，完整提示词默认展开，
  变量卡片默认收起。
- 「最近成片」状态：
  - 有可用轮次且未采用：`✓ 成片已生成 · 时间 · 来源` + `[选用成片]`；
  - 已采用最新可用轮次且目标文件存在：整行不显示；
  - patch 重新抽取导致当前版本没有 `result.mp4`：重新显示 `[选用成片]`；
  - 没有可用成片且最近一轮失败：`✗ 上次生成失败 · 时间 · 详见任务记录`；
  - 一轮都没有：整行不显示。
- 不持久化展开状态，保持每次进入页面一致的行为。

## 4. 折叠与摘要

- 页面主体的折叠区使用原生 `<details>/<summary>`，摘要行左右布局：
  左侧标题，右侧灰色状态。
- 摘要由现有数据计算，不新增接口：
  - 素材：`info.submit_selected` 与 `info.assets`；
  - 提示词：`info.prompt.placeholders`、`vars`、`labels`、`help`；
  - 最近成片：`info.rounds`、`info.adopt_round`、`info.extracts`。
- 生成设置与扣费额度不再是折叠区，也不在主体显示摘要；它们的状态只由底栏
  的控件本身表达。
- 摘要刷新复用 `renderAll()`；底栏的状态文字与按钮由 `renderSubmitBar()` 统一更新。
- 状态值缺失时显示 `—`，不显示空摘要行。

## 5. 模板别名机制（契约变更）

### 5.1 语法

占位符写成 `{键|显示名|填写说明}`，后两段是给人看的，不进入成片提示词：

```
【任务】只编辑 <视频1> 中指定的主体：把 {subject|原主体|写画面里要被替换的主体；模型据此判断改哪个对象。} 重绘成 {target|重绘结果|写替换后的外观与风格；决定成片里主体最终长什么样。}。
情节：{plot|情节|按时间顺序写原片的动作与情节；模型据此保持动作顺序与节奏。}
```

- 第一个 `|` 后是显示名，第二个 `|` 后是填写说明；两段都允许中文、空格与斜杠，
  不允许 `{`、`}` 与换行，显示名里还不能出现 `|`。
- 只写 `{键|显示名}` 仍然有效；不写显示名或说明的占位符保持现有行为，
  页面退回键名或不显示说明。
- 同一个键在模板里出现多次时以第一次的显示名与说明为准；模板测试断言同一模板内
  同名键的显示名一致。

### 5.2 解析与渲染

改动集中在 vrgen `src/vrgen/prep/prompt.py`：

- 占位符正则扩为 `\{([A-Za-z_][A-Za-z0-9_]*)(?:\|([^{}\r\n|]*))?(?:\|([^{}\r\n]*))?\}`。
- `template_placeholders()` 仍返回键名列表，返回值与顺序不变。
- 新增 `template_aliases(text) -> dict[str, str]` 与
  `template_help(text) -> dict[str, str]`，分别收集显示名与填写说明。
- `render()` 先把整个占位符归一成 `{键}` 再 `format_map`，成片提示词逐字节
  与改造前一致；新增回归测试对现有模板做同一组变量的渲染前后比对。
- 空显示名或空说明按未写处理。

### 5.3 prompt show / save 的输出

`docs/case-model.md` §4 的 JSON 增加两个字段：

```json
"labels": {"subject": "原主体", "target": "重绘结果"},
"help": {"subject": "写画面里要被替换的主体；模型据此判断改哪个对象。"}
```

- 只包含写了显示名/说明的占位符；旧调用方可以忽略。
- `show` 与 `save` 都返回，页面保存变量后立即拿到最新显示名与说明。
- `template_text` 保持原样（含 `|显示名|说明`）；「查看模板骨架」按原样显示，
  并在标题旁注明 `|` 后依次是页面显示名与填写说明，不进入成片提示词。
- 前端用 `labels[键] || 键` 渲染显示名，用 `help[键]` 渲染说明，不写任何键名映射。

### 5.4 防漂移测试

vrgen 新增模板覆盖测试：遍历 `templates/*.md`，断言每个非几何、非计算占位符
都带显示名与填写说明，且同一模板内同名键的显示名一致。以后新增可编辑变量
却忘了写显示名或说明，CI 直接失败，而不是在页面上退化成英文键名。

几何键与计算键不强制写显示名或说明；页面不为它们生成输入框，也不单独列一段
“自动填入”。

### 5.5 模板正文改动

| 模板 | 加显示名与填写说明的占位符 |
|---|---|
| character-repaint | subject 原主体、target 重绘结果、plot 情节、motion_rule 动作重演规则、preserve 必须保持、allowed_changes 允许变化 |
| gen-edit | 同上 |
| gen-multi | subject 主体与最终结果、target 目标外观、plot 动作段、preserve 场景、镜头与声音锁定、allowed_changes 允许变化 |
| 360-closure | theme 主题 / 场景、plot 情节、action 动作、style 目标画面、allowed_changes 允许变化 |

## 6. 提示词编辑区

- 完整预览：按 `【…】` 分段渲染，段间留白；字号 0.85rem、行高 1.65；
  高度随内容增长，65vh 封顶后内部滚动。
- 变量卡片：`<details>`，摘要行只放「显示名 + 键名」，下一行是该字段的填写说明
  （来自模板的第三段）；正文是 `<textarea>`，用同一个 `autoGrow()` 辅助函数在
  渲染与输入时按 `scrollHeight` 调整，最小 3 行、最大 40vh。
- 不再在摘要里显示字数或内容片段：片段只取前 40 字，编辑靠后的内容时看起来
  “没有更新”，反而误导；字数也不承担决策作用。
- 只读键（`geometry_keys`、`computed_keys`）不生成输入框，也不单独列出；
  它们的值已经体现在完整提示词预览里。
- 「添加变量」收进折叠组，减少主视线干扰。
- 保存竞态：变量从 `change` 改为 `input` 防抖保存（400ms）；提交与预演处理函数
  都先 `await flushPromptSaves()` 再发请求，保证 `prompt-vars.toml` 已落盘。
- 重建抑制：`renderPrompt()` 以「键集合 + 只读标记」为签名，签名不变时只同步
  输入框的值，不重建输入框，避免其他请求重画时丢失焦点和未失焦文本。

## 7. 底部提交条

- 位置：`#pnl-generate` 内新增 `#submitBar`，`position: fixed; bottom: 0`，
  左右与页面边距对齐，`z-index` 高于内容、低于弹层；只在生成步骤显示。
- 两行结构：
  - 第一行：`生成设置` 标签 + 模式、比例、输出分辨率、输入分辨率、时长五个
    原有控件 + `[预演检查（不扣费）]` 与 `[提交生成]`；两个按钮的完整说明
    （不提交、不扣费）放在 `title` 里。
  - 第二行：`扣费额度` 标签 + 项目、剧集、生成会话三个原有控件 + `[刷新]` +
    状态文字（素材数、门控原因、预演状态）；会话的获取/保存状态是下拉框旁的
    独立小字。
- 控件沿用原有 id 与事件处理，`params.js` 的 `renderGenParams()`、
  `renderSessions()`、`saveGenParams()`、`onSessionChange()` 不改逻辑，
  只改模板里的宿主位置。页面主体不再 include `partials/params.html` 与
  `partials/sessions.html`，这两份内容合并进 `partials/submitbar.html`。
- 保留 `genFixed`、`genParamsHint`、`sessionHint` 三个挂点：`genFixed` 隐藏，
  文字转成「生成设置」标签的 `title`；`genParamsHint` 隐藏后由状态行读取；
  `sessionHint` 作为会话下拉框旁的独立小字。这样 `params.js` 不需要为
  “元素被移走”加重构分支，也不会出现两个写入方抢同一行文字。
- 状态优先级：`generation_params.error`（参数读取失败）→ `gates.generate.reason`
  （门控缺口，红色）→ `genParamsHint`（尺寸/档位提示）→ 预演状态 →
  `素材 N 项`。同一时刻只显示一条，避免底栏堆字。
  `sessionHint` 是会话下拉框旁的独立小字（获取中 / 已保存 / 获取失败），
  不参与这条优先级链，避免两个写入方互相覆盖。
- 门控不满足时两个按钮都禁用；不用 `alert` 报告门控原因。
- 显示条件：`showStep("generate")` 时给 `<body>` 加 `gen-step` 类，
  CSS 用 `.gen-step #submitBar { display: flex }`。
- 页面底部留白：`ResizeObserver` 监听 `#submitBar` 的高度，写入
  `--submit-bar-h`，`body` 的 `padding-bottom` 使用该变量。底栏换行变高时
  留白跟着变，不写死像素。
- 窄屏时两行各自换行，底栏高度随内容增长；下拉框设置 `min-width` 与
  `max-width`，项目名/会话名截断并给 `title`。
- 原页面内的提交与预演按钮删除，只保留底栏这一处。

## 8. 预演一致性与复用

预演已经走的是真实提交的本地准备路径，复用由台账保证，不需要新增接口：

- `vrgen submit --dry-run` 会用 `run_key`（提示词 + 母版 + 参数 + 素材指纹）
  建立或命中一条 `stage=prepared` 的轮次；同样的输入再次提交时，
  `prepare_round` 直接复用这一轮，不新建轮次、不重新缩放素材。
- 页面今天无法判断「上次预演是否仍代表当前选择」：轮次列表不携带参数，
  且归一化后的参数（`duration_s`、上传尺寸等）无法与页面原始选择逐字段比较。

页面只做**输入快照**，不复制服务端的归一化逻辑：

- 点预演时，先 `flushPromptSaves()`，再把当前可控输入压成签名：
  - 素材组：勾选 id 顺序、每个素材的 mtime/size；
  - 参数组：模式、比例、输出分辨率、输入分辨率、时长；
  - 提示词组：模板、全部变量值、渲染后的提示词；
  - 额度组：项目、剧集、会话。
- 预演任务完成（`/api/task` 的 `last` 里出现本 case 的 `dry_run` 任务）后，
  记下「预演通过」；当前签名与预演签名逐组比较，得出「未改动」或
  「已改动：素材、提示词」。
- 签名只存在页面内存里，刷新即失效。重新预演很便宜：输入没变时直接命中
  已有轮次。状态文案说「当前选择未改动，可以直接提交」，不声称与服务器
  身份完全相等。
- 预演失败时第二行显示 `✗ 预演未通过 · 详见任务记录`，失败 tail 已在任务面板。
- 真实提交不因预演过期而阻止，只做提示；提交后清除预演状态。

## 11. 验收

契约与单测：

- `vrgen prompt show --job dacne` 输出含 `labels`，且 `render()` 结果不含 `|`。
- 现有四个模板的渲染结果与改造前逐字节一致（同一组变量）。
- vrgen、vrstudio 的 `uv run pytest` 全绿，`uv run ruff check .` 干净。

浏览器手工验收（用 dacne 与一个 gen case）：

1. 进入生成步骤，页面主体没有生成设置与扣费额度区域；所有控件只出现在底栏。
2. 底栏第一行五个设置控件、第二行三个额度控件都能正常读取与保存；
   下拉值改变后 `generation.toml` 立即更新。
3. 素材勾选、模式切换、会话切换后，底栏状态文字同步更新。
4. 门控不满足时两个按钮禁用并显示具体原因；满足时可提交。
5. 底栏换行导致高度变化时，页面底部留白跟着变大，最后一行内容不被遮挡。
6. 提示词预览随内容增高，长 `plot` 能在卡片内完整编辑。
7. 变量显示「原主体  subject」与下一行的填写说明，切换模板后两者随之变化。
8. 编辑变量后立刻点提交，`prompt-vars.toml` 的值已更新，`prompt.txt` 与页面一致。
9. 预演通过后状态行显示「当前选择未改动」；改素材/参数/提示词/额度任一组后
   显示已过期并列出变化组；重新预演后恢复。
10. 预演后不做修改直接提交：`runs/<job>/` 不新增轮次，提交复用预演那一轮。
11. 生成成功后「最近成片」出现，点「选用成片」跑 adopt 任务，门控与步骤条更新；
    已采用且目标文件存在后该行消失。
12. 预演轮次不再出现在页面上；失败轮次不显示为可选用项。
13. 三条流程页面都能打开；关键帧工作台与改造前一致。

## 13. 风险

- 固定底栏常驻八个控件，占用约 90–140px 视口高度；窄屏换行后会更高。
  用 `ResizeObserver` 动态留白，并在验收里检查三种流程与窄屏。
- 长项目名/会话名会撑开下拉框：设置 `max-width` 并截断，完整值放 `title`。
- 模板语法变化影响所有模板：用渲染字节等价测试与模板覆盖测试兜住；
  历史轮次的 `prompt.txt` 是落盘结果，不受影响。
- 预演签名只覆盖页面可控输入，vrgen 配置默认值或磁盘上的素材被外部替换时
  可能误报「未改动」；因此文案只说「当前选择未改动」，且素材签名包含
  mtime/size。
- 删除轮次列表后，页面上无法改选旧轮次；CLI `vrgen status` 与
  `vrstudio generate adopt --round` 仍是兜底路径。
- 文案改名与现有页面测试冲突：WP2 同步更新断言。
