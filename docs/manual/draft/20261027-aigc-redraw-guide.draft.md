# 第一章　开始之前

## 1.1 你需要先认识的三个词

这一节只出现三个新词，其余词在用到时再解释。

- **360 全景视频**是一段可以任意转头的视频。普通视频只有一个固定视角，全景视频把四周全部拍下来，观众在播放器里拖动鼠标就能看向任意方向。本系统处理的源片都是这种视频。
- **重绘**是指让 AI 按你的提示词重新画一遍画面，同时尽量保留原来的动作与镜头运动。本系统的重绘只改你指定的区域或指定的画面比例范围，不会把整段视频剪碎重做。
- **case** 是一次完整工作的容器。一个 case 绑定一段源视频和一条流程，从选区一直做到成片；同一个 case 的中间结果、版本和成片都保存在一起，关闭网页后再打开还能接着做。

**这三条流程有什么区别。** 选错流程会白费时间，所以先看这一小节。

- **局部重绘**适合源片整体可用、只有一小块区域需要改的情况，例如画面里有一个白模人物需要换成真人。它要做选区、抽取、首尾帧、生成、合并、对比六步，是最长的一条流程。
- **全画幅重绘**适合整段画面都要重新生成的情况。它要把画面先扩充成 AI 能接受的宽高比，生成后再裁回原尺寸，共四步。
- **简单生成**适合不需要对准原片、只要按提示词新做一段视频的情况。它只有一个生成步骤，不需要源视频，也不需要选区和首尾帧。

如果仍然拿不准，按这个顺序判断：需要保留原片的大部分画面就选局部重绘；需要整段重画但保留原片的镜头运动就选全画幅重绘；只需要新做一段视频就选简单生成。

# 第三章　局部重绘（patch）

局部重绘适合「源片整体可用、只有一小块需要改」的情况，一共六步：选区、抽取、首尾帧、生成、合并、对比。页面顶部的步骤条会一直显示这六步，已经完成的步骤显示为完成状态。

## 3.1 选区：决定改画面里的哪一块

选区这一步做三件事：选择一个视口方向，在视口里框出一块区域，再定下要处理的帧范围。

页面分成左右两栏。左栏是「全景与视口」，副标题写着「点哪里，视口中心就在哪里」。右栏是「选区与抽帧范围」。

操作顺序固定为下面五步，跳步会导致后面的按钮点不动。

1. 在左侧全景画面上点一下，确定看哪个方向。可以用「播放」「暂停」和逐帧按钮找到动作最好的那一帧。
2. 在右栏「视口尺寸」里选一个尺寸。只有一项时不用选，说明系统只配置了这一种。
3. 在右侧预览图上按住鼠标左键拖动，画出一个框，松开鼠标即自动保存。框住的就是 AI 要重绘的范围。
4. 用方向摇杆 ↑←→↓ 微调视口。摇杆默认速度是 1.0°/秒，可以改小再微调。
5. 在「抽取范围」的两个数字框里填开始帧和结束帧，点「保存范围」。

# 第四章　全画幅重绘（fullredraw）

全画幅重绘适合「整段画面都要重画、但镜头运动要保留」的情况。它只有四步：扩充画面、生成、裁回原尺寸、对比。

**为什么需要先扩充再裁回。** AI 生成视频时只接受固定的宽高比，而全景视频是 2:1 的。直接生成会在左右接缝处出现断裂，所以系统先把画面左右各复制一段做冗余，加遮罩后交给 AI，生成完成后再按记录把冗余部分裁掉，接缝就落在可接受的位置。

页面只有一个主面板「扩充与裁回」，里面是流程条「扩充画面 → 生成 → 裁回原尺寸」和两个按钮。扩充比例由系统固定为 21:9，页面上没有比例输入框，不需要找。

# 第六章　三条流程怎么选

三条流程的差别可以用一句话概括：局部重绘改一块，全画幅重绘改全部，简单生成重新做。

- **局部重绘**需要源视频，需要做选区、抽取、首尾帧，共六步，最终产物是贴回原片的成片。它最费时间，但改动最精准，原片没被选中的部分一个像素都不动。
- **全画幅重绘**需要源视频，需要先扩充再裁回，共四步，最终产物是裁回原尺寸的整片。它适合整段画面都要换风格的情况，接缝靠扩充与裁回处理。
- **简单生成**不需要源视频，也不需要选区，只有一个生成步骤，最终产物是 AI 直接生成的视频。它最快，但与原片没有对应关系。

# 第七章　常见问题与报错处理

**网页打不开怎么办。** 先确认地址是 `http://127.0.0.1:8760/`，再确认服务在运行。服务由管理员启动，你不需要执行命令。局域网访问时地址会换成管理员给的 IP。

**上传时报「文件超过上限」怎么办。** 单个文件上限是 10 GB，超过后服务端直接拒绝，分片不会开始传。先压缩或裁剪文件，再重新上传。

**上传时报「只支持 mp4/mov/mkv/avi 与 png/jpg/webp」怎么办。** 文件后缀不在允许列表里。换格式导出后重传，不要只改文件名后缀。

**选区保存失败怎么办。** 先看帧范围，「帧范围要在 0–N 之间，且开始小于结束」是最常见的原因。改成合法范围后重新保存。仍然失败时刷新页面重试。

**抽取按钮点不动怎么办。** 顶部两个状态里「✓ 选区已保存」没有亮。回到选区步骤把选区与帧范围保存一次。

**首尾帧的生成按钮点不动怎么办。** 页面会写出原因，按原因处理：「先完成抽取并准备两张原始帧」表示抽取没完成；「先添加一张人物三视图并设为主三视图」表示参考图缺失；「先生成并挑选首帧定稿」表示尾帧步骤在等首帧。

**「预演已过期」是什么意思。** 预演检查通过之后，只要改了提示词、素材或参数，之前的预演就作废了，需要再点一次「预演检查（不扣费）」。「预演通过，当前选择未改动」表示预演仍然有效。

**底部出现「提交条件未满足」怎么办。** 提示后面会直接写缺什么，例如「没有勾选任何素材——至少勾选一项再生成」。「firstLastFrame 需要恰好一张首帧定稿和一张尾帧定稿」表示清单里图的角色或数量不对。

**任务一直排队或失败怎么办。** 排队位置在任务中心能看到，任务量少时会自动前进。失败时打开该任务的详情，看「日志尾部」，把内容发给管理员。

**页面顶部提示「可能正在编辑此 case」怎么办。** 另一个人也打开了同一个 case。先和对方确认由谁修改，不要两边同时保存，否则会互相覆盖。

**找不到成片怎么办。** 三个地方分别对应不同阶段：生成页的「生成记录」是 AI 原始结果；合并页或裁回页的「成片」是最终成片；对比页只是播放，不产生新文件。文件路径见下一章。

**对比页提示「这个浏览器不支持 WebGL，全景对比看不了」怎么办。** 换 Chrome 或 Edge 的新版本，并确认没有关闭硬件加速。

# 第八章　成片文件在哪里

所有中间结果与成片都保存在这个 case 的目录里，目录名就是 case 名称，位于 vrstudio 仓库的 `cases\` 下面。下面按用途列出会看到的子目录与文件。

- `out\` 存放合并或裁回后的最终成片，文件名带时间或轮次，例如 `20261023-085718_space.mp4`。交付时通常取这里的文件。
- `extracts\<版本>\` 存放每次抽取的结果，其中 `result.mp4` 是该版本对应的片段，`clip.mp4`、`clip_mask.png`、`clip.json` 是选区产物。
- `derived\` 存放预览代理与选区缓存，可以重新生成，不是交付物。
- `assets\` 存放加入这个 case 的素材、首尾帧定稿图与参考图。
- `case.toml` 与 `case-meta.json` 记录这个 case 的流程、源视频、参数与采用结果，不要手工修改。

简单生成流程没有抽取与合并产物，结果直接放在 case 根目录的 `result.mp4`，采用后的记录在 `case.toml` 里。

在网页上确认最终文件的三个位置是：合并页右栏「成片」、裁回页右栏「成片」、对比页顶部的「右路成片」下拉。只要这三处之一能看到，文件就一定在 `out\` 目录里。

### 截图怎么生成

制作分三步：起一个不影响他人的实例，用 Playwright 截图并注入标注，最后逐张读图验收。

**第一步：起一个专用实例。** 你的 8760 服务可能正在被使用，直接在里面操作会在真实的 case 上写占用标记，截图里也会出现别人的占用警告。做法是把三个演示 case 复制到临时目录，用另一个端口启动第二个实例。

- 用到的演示 case：`walk_4k`（局部重绘，已有成片）、`ship_01`（全画幅重绘，已有成片）、`simple_gen_allMediaRef`（简单生成，已有结果）。
- 临时目录放在 `E:\VRAIGC\.manual-draft\cases\`，用硬链接复制，避免把几 GB 的视频再拷一份。
- 启动命令是 `uv run vrstudio serve --cases-dir E:\VRAIGC\.manual-draft\cases --port 8761`，截图全部针对 `http://127.0.0.1:8761/`。

**第二步：截图并注入标注。** 用 Playwright 打开页面，固定窗口为 1600×1000、设备像素比 2，语言设为中文，关闭动画与滚动条，等网络空闲后再截。

每张图都按「裁剪区域」截图，不截整个窗口。做法分两种，优先用第一种。

1. 目标是一个面板或一块连续区域时，直接对容器截图：先拿到容器的外接矩形，向外扩 16 像素留白，再按这个矩形截图。这样得到的图里只有读者要看的内容。
2. 目标是分散在页面两处的控件时，先滚动到两处都能看见的位置，再按覆盖两处的矩形截图；如果滚动也放不下，拆成两张图，不要为了凑一张而截整页。
3. 唯一允许接近整页的是每个步骤的布局图，裁到主内容区即可，浏览器外框、顶部栏、左侧导航一律不进入画面。

标注不用后期画，而是在页面里注入一层覆盖元素，再连同覆盖层一起截图。注入的内容由一份清单驱动，每一项写清目标元素、编号、是否加红框。

- 清单格式是 JSON，字段包括 `selector`（目标元素）、`text`（按文字定位，与 selector 二选一）、`number`（编号，可空）、`box`（是否画红框）、`position`（编号放在左上还是右上）、`clip`（截图区域，写容器选择器或四边数字）。
- 注入脚本读取清单，为每个目标计算屏幕位置，创建一个绝对定位的 div：2 像素红色边框表示关注区域；编号是一个 24 像素的圆形徽标，白底红边、红色数字，带白色描边保证在任何背景上都看得清。
- 每个目标只画一次，多个编号重叠时依次向右错开 26 像素。
- 截图前等 200 毫秒，确保重排完成，避免边框跳动。

**第三步：逐张读图验收。** 每张图生成后必须读一遍，检查三件事：编号没有压住控件文字、红框没有框到无关区域、画面里没有别人的占用警告或错误提示。不合格就调整清单重跑，不允许直接编辑图片。

截图脚本 `tools\capture.py` 按 `tools\shots.json` 执行，默认拍全部，加 `--only <id>` 只重拍指定的一张或几张。每张图会写三份同名文件：`shots\raw\<id>.png` 是未标注的原始画面，`shots\annotated\<id>.png` 是带编号与红框的版本，`images\<id>.png` 是最终文档引用的那一份。三份文件按同一 id 对应，日后要换图时从后往前逐级对照，能很快判断是界面变了还是标注位置变了。

### 文件放在哪里

草稿、过程截图与最终文档全部长期保留，分成四类目录。同类文件放在一起，改名或重截时只需要动一处。

- `docs\manual\output\aigc-redraw-guide.md` 是当前正式文档。图片文件名不带图号，正文用相对路径 `../images/<文件名>` 引用，图号只出现在图注里，这样章节重排不会导致图片错位。每次更新把当前文件改名为 `-1`、`-2` 依次递增，新内容写回原名。
- `docs\manual\images\` 存放最终选用的 43 张截图与 1 张对照图，文件名与正文引用一致，不带日期。
- `docs\manual\draft\` 存放这份草稿的各个版本。每次改结构前先复制一份带日期的草稿，例如 `20261027-aigc-redraw-guide.draft.md`，改坏了可以退回。
- `docs\manual\shots\raw\` 存放未经标注的原始截图，`docs\manual\shots\annotated\` 存放带编号与红框的截图。最终图片从 `annotated` 复制到 `images`，三处文件名相同，方便逐级对照。
- `docs\manual\tools\` 存放可重复执行的工具：`shots.json` 是每张图的拍摄与标注清单，`annotate.js` 负责在页面里注入编号与红框，`capture.py` 负责按清单截图，`flow_compare.py` 负责画对照图。
- `E:\VRAIGC\.manual-draft\` 只放可再生的临时内容：case 副本、浏览器用户数据、失败重拍的中间文件。这里的东西可以随时删除，不影响上面四类目录。

### 每次只更新必要部分的办法

日后界面改了或需求变了，按下面三种情况处理，不需要整篇重做。

1. 只有文字要改：把 `output\aigc-redraw-guide.md` 改名为 `-1` 或下一个未占用的序号，然后把新版写回原名；图片不动。
2. 只有一张或几张图要换：在正文里找到图片文件名，再到 `shots.json` 里按同名 id 找到这张图的清单项，执行 `capture.py --only <id>` 只重拍这几张。重拍会同时覆盖 `raw`、`annotated` 与 `images` 三处的同名文件，其余图不受影响。
3. 页面结构大改、多数图都要换：先按新界面改 `shots.json` 里的目标描述与裁剪范围，再整体重拍。旧图不要删除，移到 `shots\archive\<日期>\` 保留，方便对比新旧界面。

为了让上面三条成立，`shots.json` 里每一项都记录六样东西：图片文件名、所在页面地址、所属 case、目标元素、标注列表、裁剪范围；另外记录两项时间信息：拍摄日期与当时的 vrstudio 提交号。下次代码改动后，按提交号判断哪些页面的截图可能过期，只重拍受影响的部分。

对照图也遵守同一条规则：改图就改 `flow_compare.py` 重新生成，不直接编辑 svg 文件。
