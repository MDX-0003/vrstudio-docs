# fullredraw 目标画面优先计划（模板重排与场景指令改写）

状态：2026-11-04 用户确认三项改动（点亮现有烛台、地面改抛光镜面、模板重排），实施中。
关联：决策 81，`vrgen/templates/360-closure.md`，`cases/vf_dance_walk_02`，`docs/generate-page-plan.md` 的模板变量表。

## 1. 问题

`vf_dance_walk_02` 的 adopted 轮次（`360-closure-e5257812`）成片被用户判断为「原版视频加了一层滤镜」。逐区域核对后确认这不是采样波动，而是提示词写法的直接结果。

- `refs.json` 只提交了 `pad` 视频，参考图从未进入生成；所有风格信息只靠 `style` 变量里的几百字传递。
- 同一位置的统计：参考图地面亮度 10/90 分位为 36/92、饱和度均值 23.0；成片为 30/67 与 7.0。成片把地面压成低饱和的灰蓝，参考图是带镜面反光的暖色石板。
- 参考图里能看到、成片里没有的四个特征：每一盏灯独立的光池与平方反比衰减、地砖上的镜面反光条、受光暖与暗部冷分离、朱红与金色的高饱和。

提示词本身把模型推向全局调色：

- `style` 第一句写「只改明暗强弱，不换材质」，与目标观感需要的材质响应直接冲突。
- `allowed_changes` 要求「灯照不到的角落亮度与颜色保持原片不变」「其余区域逐像素保持原片观感」，模型照做，只能做增益映射。
- 「提亮到原片同一位置的约 1.5 到 2 倍」是不可执行的相对量，模型退化成整幅提亮。
- 「不提亮、不压暗、不去红、不加暖色、不加雾」连续五个否定句，模型对否定词处理很弱。
- 结尾「写实光影，电影质感，高对比，低饱和」与参考图相反。
- 模板把【主体保全】【允许变化】排在【风格】之前，正文定调「严格编辑、其余一个都不改」，进一步锁定最小改动。

## 2. 目标

把提示词的重心从「相对原片改多少」改成「这个场景最终应该长什么样」：

- 模板层：目标画面排在保全与允许变化之前，保全段落压缩到一两句。
- 案例层：`style` 改成绝对的目标观感，`allowed_changes` 压成一条总授权，明确允许点亮已有灯具、允许改变材质响应。
- 不改的部分：主体、数量、位置、动作、服饰、镜头、构图、时间轴、左右冗余带的逐列对应规则全部保持原样。

## 3. 模板改动

`vrgen/templates/360-closure.md` 的新顺序：

1. 【素材清单】
2. 【素材指代】
3. 【任务】
4. 【主题/场景】
5. 【目标画面】（原【风格】，变量键仍是 `style`）
6. 【情节与动作】
7. 【允许变化】
8. 【主体保全】
9. 【固定约束】
10. 【禁止】

措辞上的三处调整：

- 【任务】从「严格编辑 <视频1>：只改变渲染风格、材质与光照……除此之外画面内容一个都不改」改成「编辑 <视频1>：按【目标画面】与【允许变化】重做光影、影调、色彩、材质响应，以及明确列出的动作或情节；其余的主体、数量、位置、构图与运动保持原样。」
- 目标画面的说明从「只说明想要的视觉质感，不是画面内容清单，不得据此新增或删除任何物体」改成「只描述最终要看到的光影、材质与影调，不单独构成新增或删除物体的依据；要改变场景元素的，在【允许变化】里写明。」
- 【主体保全】压成两句；【允许变化】的引导语压成一句。固定约束的 5 条保持原样，其中第 3 条的逐列对应是冗余带闭合的硬约束，不改。

`style` 的页面显示名从「风格」改为「目标画面」，填写说明改为「写这个场景最终要呈现的光影、影调、色彩与材质响应；只影响观感，不新增物体。」

## 4. 案例改动（`vrgen_runs/vf_dance_walk_02/prompt-vars.toml`）

`theme` 只改最后一句：把「殿内不再增加任何新的灯具或其他照明」改成「不引入窗光、月光、顶光或新的器具照明」，避免被读成「不要再增加任何亮度」。

`style` 改为：

```
最终画面是一场真实的烛光夜景，不是把原片整体调亮或加一层暖色滤镜。原片只提供内容、构图与动作，光影、影调、色彩与材质反射按本节重新渲染。

一、光源与光池。殿内所有已经摆在那里的烛台、灯架与油灯全部点亮，不新增任何器具：前景宴席案上的油灯、殿中供案两侧、右侧高台基座旁、左右侧廊与后排的每一座烛台，每座都点着一簇真实火苗。火苗很小、很亮，中心接近纯白，外围一圈很短的黄橙色光晕。每个火点在周围的地砖、案面、柱身与梁底形成一片暖色光池，池心最亮，向外连续变暗，亮度按距离的平方下降；池边柔和，没有硬线。相邻光池在中间交叠，交叠处更亮。灯照不到的地方（两盏灯之间、柱子背面、殿顶梁缝、厅堂深处、画面左右下角的席面）保持深暗，最暗处接近纯黑；暗部从光池边缘一路暗下去，不是平均的灰。整幅画面平均亮度偏低，画面靠这些亮斑被看见。

二、材质响应。地面是打磨过的深色石板，表面带湿润的镜面反射：每盏灯在地砖上留下一条被拉长的暖色反光，砖缝与砖面高低差有清晰细影。朱红漆面梁柱在转折与斗拱棱角处出现窄而亮的高光。黑底描金蟠龙柱的金色纹样出现细碎的金色高光。青铜编钟、灯架与器皿是高反射金属，受光面亮、背光面暗。席面、丝绸与深衣是哑光材质，只有柔和的受光过渡。果品表面有湿润高光。人物皮肤与织物保持真实照片的质感，不塑料化。

三、影调与色彩。受光面是饱和的暖琥珀色，色温约 2500K；暗部保持中性偏冷，不带橙色。朱红是深正红，不偏橙；金色偏黄，不偏橘。整体饱和度高于原片，红色与金色尤其饱和；暗部去饱和。高光只有火苗中心允许接近纯白，其余高光有层次，不糊成白块。画面有极细的胶片颗粒；没有雾、没有光柱、没有镜头光斑、没有整体蒙灰。

四、细节。梁架木纹、斗拱雕花、柱身贴金纹样、地砖磨损与席面编织纹理清晰可辨，微对比强；不糊、不油画化、不塑料化。三米以内的人脸与衣物可辨认，受光面暖、背光面暗。

五、全片一致。以上光影、影调、材质与色彩作用于整幅画面（含左右两条冗余带），全片保持同一套，没有切换与转场。人物的数量、位置、朝向、动作、服饰款式与纹样、进入与离开画面的时间全部与 <视频1> 一致；不新增人物、道具或灯具，不改变镜头与构图。
```

`allowed_changes` 改为一条：

```
1. 主体：整幅画面的渲染方式与现有灯具的点燃状态；变化内容：按【目标画面】重做曝光、光比、影调、色彩与材质反射，并把画面里已有的每一座烛台、灯架与油灯点亮（火焰长在原器具上）；时间：全片；幅度：不改变任何物体的形状、数量与位置，不新增器具、人物或道具，不改变动作、服饰、镜头与构图，左右两条冗余带同步变化。
```

`plot` 与 `action` 不改。

## 6. 风险与回退

- 模板是所有 fullredraw 案例共用的。`palace_01` 的 style 依赖 `@Image1` 提供光照，`ship_01` 依赖较大的环境变化；两者都在 `allowed_changes` 里写了授权，重排不改变它们的内容，只改变阅读顺序。回退方式是恢复模板的段序，案例变量不受影响。
- 点亮烛台会新增火苗，属于【允许变化】明确列出的场景元素变化；若平台把这理解成新增物体而拒绝，回退为只提亮已有灯焰。
- 纯提示词无法保证每盏灯的光池落在实物位置上。若 480p 试跑仍退化为整体提亮，下一步按 `lighting_ref` 提交参考图，不改模板。

## 7. videoEdit 的氛围参考（2026-11-04 追加）

用户在两种模式之间得到的对照结论是：videoEdit 的动作与时间轴跟随输入，但画面观感变化有限；allMediaRef 的光感更好，但节奏不能严格对齐。同一份新提示词的两轮实测确认差异来自模式而不是提示词：

- `360-closure-414650a6`：videoEdit，模型 37，1080p，297 帧 / 12.384 秒。
- `360-closure-8e6bcfa3`：allMediaRef，模型 37，480p，313 帧 / 13.056 秒。
- 两轮 `prompt_hash` 都是 `695aa04ecbf57ff8`；allMediaRef 的成片能看到独立光池，videoEdit 的地面仍没有镜面反射。

本轮保持 videoEdit，并加入一张氛围参考：

- `cases/relight_web_01/assets/i3_model_4k_cc92.png` 作为 `lighting_ref` 进入 `vf_dance_walk_02` 的提交集。它与 case 里已有的 `assets/i1_i3_model_4k_cc92.png` 逐字节相同（SHA256 `8d7db7a6…`），因此复用 `i1`，不复制第二份文件。
- 提示词新增【氛围参照】段：`@Image1` 只提供色温、亮暗对比、冷暖分离、空气质感与地面和漆面的反射方式；机位、构图、比例、人物、陈设与建筑一律以 `<视频1>` 为准；参考图结构与视频不符时不得带入。
- 提交集出现非 mask 图片后，装配器会自动追加冗余带 mask。提示词里补一句「最后一张黑白图只说明冗余带位置，不是编辑范围」，避免 videoEdit 把白带当成唯一编辑区域。
- `generation.toml` 的 `mode` 改回 `videoEdit`，`resolution` 仍是 480p。

风险：带参考图的 videoEdit 可能被平台判成参考生成并拒绝（`docs/prompt-rules.md` §3.2 的实测）。失败原因会写进 `run.json` 的 `notes`；若被拒，下一级手段是减少图片或改回 allMediaRef。
