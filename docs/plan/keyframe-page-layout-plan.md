## 0. 已确认的分支决策

1. **只做 A2（通栏纵向），B（300px 素材栏）不落地。** 2026-10-26 讨论确认。B 的常驻素材栏会让提示词被压到页面最下方，而提示词是本页唯一需要对照输入修改的内容，取舍上不如抽屉。
2. **输入四格与提示词编号一一对应**：图1 = 当前步骤的原始帧，图2 = 人物三视图，图3 = 首帧定稿（仅尾帧步骤），目标 = 本步骤要定稿的那一帧。提示词模板里写的「图1/图2/图3」就是这四格中的前三格。
3. **三视图走就地抽屉**，抽屉里给缩略图、打开原图、上传；不常驻、不跳生成页。
4. **生成参数与生成按钮归候选面板头部**，页面顶栏只留「首帧/尾帧」开关与「交接给视频步」。
5. **不新增后端接口，不改 `run.json`、`clip.json`、`_pad.json` 与 CLI 契约。** 三视图缩略图复用现成的 `/img/asset/<case>/<id>`，候选图复用现成的 `/img/keyframe/...`。

## 1. 问题与根因

用户原话（节选）：

> keyframe、extract 都存在页面中央的空白区域……首尾帧模块也是展示了 4 张图片后，右侧存在大块空白……keyframe 页面里需要手动选择人物三视图，但被选的三视图，不仅在 keyframe 页面下无法预览，还需要到另一个页面上去查看、增删。

前端的空白不是配色问题，是三条排布规则叠加的结果：

1. **链条被限宽**：`.frame-card` 写死 `max-width: 360px`，外层面板却是满宽的。两张原图加箭头与视频节点只占约 800px，1440 视口下右侧空约 350px，1920 视口下空约 700px。
2. **定稿图是「追加」而不是「占位」**：首帧定稿作为 `.picked-preview` 塞在原图卡内部，一选就多出一张图的高度，两张原始帧被撑成上下两截，链条不再是横向一条线。用户说的「4 张图片」其实是两列卡片各自上下堆叠出来的。
3. **两列网格按「左短右长」配对**：`.keyframe-layout` 是 `1fr 1fr` 加 `align-items: start`，人物三视图只有一行下拉框，图片步提示词有三段输入，短的那块下面必然空出一截。

第四条不是排布问题，是信息缺位：提示词模板按「图1 原始帧、图2 三视图、图3 首帧定稿」分工，页面上却从没把这三者并排展示过，所以选完三视图既看不到图，也不知道它充当图几。

抽取页的空洞是同一类问题：`.step-layout` 也是两列 `align-items: start`，左边「抽取」只有三行摘要，右边「输出文件」有五条文件行，每行左栏下方都留白。

## 3. 设计

### 3.1 首尾帧页结构（自上而下）

```
┌ 页面标题：case 名 + 流程标签                                  已保存 ┐
├ 步骤条：选区 / 抽取 / 首尾帧 / 生成 / 合并 / 对比 ───────────────────┤
├ 顶栏：[首帧|尾帧]                             [交接给视频步] 禁用原因 ┤
├ 图片步输入（满宽）                                                    │
│  ┌图1 原始帧─┐ ┌图2 三视图──┐ ┌图3 首帧定稿┐ ┌目标 定稿────┐        │
│  │ 16:9 缩略 │ │ 16:9 缩略  │ │ 尾帧才启用 │ │ 定稿后填图 │        │
│  └──────────┘ └───────────┘ └───────────┘ └───────────┘        │
├ 首帧候选（满宽）  img-xxxx · 2K · 4 张   [2K▾][4 张][刷新][生成]    │
│  ┌─1─┐ ┌─2─┐ ┌─3─┐ ┌─4─┐   点任意一张即定稿                         │
│  └───┘ └───┘ └───┘ └───┘                                            │
│  最近一次生成任务（默认折叠，失败时自动展开）                          │
├ 图片步提示词（满宽，三列变量）                                        │
└──────────────────────────────────────────────────────────────────────┘
```

四格固定等宽（`grid-template-columns: repeat(4, minmax(0, 1fr))`），槽位高度只由 `aspect-ratio: 16 / 9` 决定，不随是否定稿变化。1440 视口下每格约 266px，1920 视口下约 386px（原型实测）。

### 3.2 数据与组件

- **图1**：`info.raw_frames` 里 `first_frame_raw` / `last_frame_raw` 按当前步骤取，沿用现有 `RawFrame.url`（`/img/asset/...`）与 `open_url`。
- **图2**：`info.keyframe.sheet` 是资产 id，缩略图用组件里已有的 `assetUrl(id)`；文件名与打开入口用 `info.keyframe.sheet_candidates` 里同 id 的那一条。候选结构没有 `name`/`exists`，需要一层适配：`{ ...candidate, name: candidate.label, exists: true }` 才能喂给 `FileOpenLink`。
- **图3**：`info.keyframe.first`（`KeyframePick`，带 `file` 与 `asset`）。只在 `step === 'last'` 时渲染图片，首帧步骤显示禁用占位与「尾帧步骤才用」。
- **目标**：`step === 'first'` 取 `keyframe.first`，`step === 'last'` 取 `keyframe.last`；有定稿时铺满整格，没有时显示虚线占位。
- **候选**：沿用 `fetchKeyframeRounds` 与 `stepRounds`，`.candidate-card` / `.candidate-wrap` 类名保留（现有单测按这两个类名断言链接位置）。
- **抽屉**：`el-drawer`（`direction="rtl"`，宽 380px），列表来自 `keyframe.sheet_candidates`，选中调 `setKeyframeSheet`，上传开 `AssetUploadDialog`。
- **交接**：`handoffKeyframe` 不变；按钮在顶栏，禁用原因取现有的「首尾帧都定稿后才能交接」条件。

### 3.3 交互规则

1. **步骤开关**：切换只改本地的 `step`，重新拉对应提示词（现有 `watch(step)`）；首帧定稿后仍自动切到尾帧并刷新提示词（现有 `pick()` 的行为保留）。
2. **点候选定稿**：调 `pickKeyframe`，成功后 `emit('updated')`；目标格与图3随 `props.info` 更新，不需要额外本地状态。
3. **三视图抽屉**：打开时按当前 case 列候选；点某张即绑定并关闭；上传按钮打开素材上传对话框，角色预设 `subject_ref`；上传完成不自动绑定（多文件上传时自动绑第一张容易绑错），刷新候选后由用户点选。
4. **交接**：`keyframe.complete && !stale` 才可点；禁用时按钮右侧常显原因文字，不靠悬停。

### 3.4 令牌与响应式

- 全部使用现有令牌（`--space-*`、`--radius-*`、`--color-*`），不新增颜色或字号。
- 断点沿用现有 `1280px`：四格改两格、候选改两列、变量改一列；再窄时（<900px）四格改一列。
- 面板间距统一 `var(--space-4)`，单列纵向，不再出现左右不等高的配对。

### 3.5 与原型的两处偏差（需要评审确认）

1. **保留任务状态与日志**：原型没有这块，但当前页面用它显示失败原因与任务尾部。方案是收进候选面板底部的「最近一次生成任务」折叠行：常态一行（状态标签 + 任务 id + 排队位），失败时自动展开 `error`，日志尾部放在折叠内容里。依据 `DESIGN.md` §5「状态必须可见、长内容默认折叠」。
2. **四格继续用 `/img/asset` 的 320px 缩略**，这一点与原页面相同，本轮不改伺服面。显示宽度约 266px，1x 屏够用；2x 屏会略软。若后续要原图，`/file` 路由已经存在，替换图片地址即可，不需要新接口。候选图仍走 `/img/keyframe/...`，它返的是候选原图字节。

## 7. 风险与回退

- **首屏变长**：单栏纵向，1440×900 下提示词在首屏以下。生成与交接都在顶栏常驻，不滚动也能完成主流程；提示词是本页低频操作，接受这个代价。
- **三视图按钮藏在格子里**：「查看 / 更换」是文字链接，首次使用可能不易发现。回退方案是在图2 缩略图上叠加整卡点击区。
- 回退方式：首尾帧页的改动集中在 `KeyframeStep.vue` 一个文件（连同它的单测），`git revert a0f51e7` 即可恢复旧排布；抽取页同理 `git revert 8695fd2`。不涉及数据与契约。
