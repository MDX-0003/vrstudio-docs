## 1. 目标

在真实浏览器里验证新前端 `/next` 能完成 patch 流程的全部必经动作，而不是只验证接口返回 200。

两条路径都必须覆盖：

1. **无首尾帧路径**：跳舞视频只取中间段，`videoEdit` 模式重绘动作，提交集是 `clip + subject_ref`。
2. **有首尾帧路径**：走路视频使用完整片段，先抽取首尾帧，再让图片模型对同一组首尾帧各生成 4 张候选，挑选后以 `firstLastFrame` 生成视频。

验收重点：

- 每个必经按钮都能点击，并产生预期结果。
- 页面显示与后端台账、文件系统一致。
- 刷新页面、切换步骤、任务失败、并发写入时状态不丢、不误导。
- 两条路径都能完成采用、合并与对比，对比页能正常播放和同步。

## 2. 不做什么

- 不测试 gen 与 fullredraw 的完整生成流程；它们不在本次 patch 验收范围。
- 不修改现有 `dacne`、`walk_4k` 的 case 文件、提示词与提交集。
- 不把生成的视频、图片和运行日志提交进 git。
- 不在本次计划阶段启动真实生成；执行前需要确认额度与会话。

## 3. 测试环境

### 3.1 服务与目录

- 后端：`uv run vrstudio serve --host 127.0.0.1 --port 8762 --cases-dir E:\VRAIGC\vrstudio\cases_qa`
- 新前端：`http://127.0.0.1:8762/next/`

- `cases_qa` 是本次专用 cases 根，现有 `cases/` 不动。

- 参考素材只从现有 case 的 `assets/` 或 `sources/` 取，不修改原件。
- 任务日志会落在 `logs/tasks/`；截图与结果记录在 `docs/test-runs/`，生成的媒体不进 git。
- 测试结束后是否删除 `cases_qa`，等验收结果复核后再决定。

## 4. 执行顺序

1. 环境预检与门禁确认。
2. 跳舞路径：新建、上传、选区、抽取、生成、采用、合并、对比。
3. 走路路径：新建、上传、选区、抽取、首尾帧 4+4、交接、生成、采用、合并、对比。
4. 页面元素与异常检查：导航、列表、提示词、任务中心、上传边界、并发、错误态、响应式。
5. 汇总证据、记录缺陷、给出通过/不通过结论。

两条路径先做跳舞路径，因为它没有首尾帧，能先验证基础执行链路；再做走路路径，验证首尾帧分支。

**A3 选区**

**A6 预演与提交**

- 浏览器上下文 A 打开 `qa_videoedit_1023`；上下文 B 再打开同一 case。
- 预期：B 看到占用者提示；锁只提示不阻断。
- A 与 B 同时修改提示词并保存；后保存者收到 409 冲突对话框；默认“重新加载”生效；取消后页面保留本地内容但再次保存仍冲突。
- 预期：revision 不匹配时页面不静默覆盖。

**U5 错误与边界**

- 停掉后端，刷新页面：502/504 显示“后端服务没有启动”，不是无限转圈。
- 访问非法步骤 URL，预期重定向到该流程第一步并提示。
- 访问不存在的 case，预期 404 明确提示。
- 缺失素材/文件时，页面显示“文件缺失”，不假装可用。
- 长提示词、长路径、长文件名在 1280/1440/1920 下不横向溢出；底部提交条不遮挡内容。

**U6 响应式与可访问性**

- 1280、1440、1920 三个宽度检查侧栏、表格、素材行、底栏、对比控制条。
- Tab 键能到达主要按钮与输入框；焦点样式可见；错误提示与输入框关联。
- 选区快捷键：空格播放/暂停、左右箭头逐帧；对比页左右方向键微调分割线。

## 9. 风险与停止条件

- **额度不足**：记录平台错误与任务 ID，停止真实提交；不要用重复提交碰运气。
- **平台生成失败**：保留失败轮次与日志，页面应显示具体原因；继续做 UI 与已有轮次验收。
- **首尾帧候选少于 4 张**：记录平台返回数量；如果页面把它当作 4 张完整批次，判为失败。
- **时间拼接异常**：如果 `_frame` 时长、首尾帧或动作区间不对，判为失败，不用对比页“看起来差不多”掩盖。
- **测试数据污染**：一旦发现写进现有 `cases/`，立即停止；本次只允许写 `cases_qa`。
- **服务崩溃**：保留终端日志与浏览器控制台，修复后从当前用例重跑，不跳过失败步骤。
