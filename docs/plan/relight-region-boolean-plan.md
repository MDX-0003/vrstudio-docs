# 重打光区域选区的挖空渲染与几何式布尔方案

状态：已批准并实施（2026-11-13，用户口头批准后直接实施），对应决策 100。
WP1（叠色渲染 + 排序）与 WP2（减去/相交几何布尔）已落地，代码见 vrstudio 提交
`8b38940`；前端 251 条单测全绿、ruff 干净，浏览器端到端验收待做。
前置决策：88/89（区域参数覆盖与极点盖帽）、91（时间区间）。
用户反馈来源：美术用户希望重叠选区之间能做 PS 式布尔运算（「A 选区独占重叠区域，B 选区
缩小对应范围」），且操作习惯对齐 PS。本文是该反馈经过需求澄清（两轮问答，2026-11-13）
之后的方案稿。

## 0. 结论

- **重叠语义不变**：引擎仍按「列表顺序，后建的在上，上层独占重叠区、逐参数覆盖」合成，
  `regions.json` 契约、引擎代码、两侧测试全部零改动。
- **减法效果用渲染兑现**：画布填充从「每个区域独立填色」改为「自下而上按列表顺序叠色，
  上层颜色盖住下层」，用户在画布上看到的就是引擎实际生效的参数归属；等于把「B 减去与
  A 的重叠」在视觉上表达出来。
- **顺序操作显式化**：区域列表与画布选中态提供置顶 / 上移 / 下移 / 置底，用户不再需要
  理解「数组顺序」这个隐性概念。
- **PS 式布尔是几何编辑，不是合成规则**：绘制模式提供「新选区 / 从选中区域减去 / 与选中
  区域相交」三档（工具栏按钮 + 快捷键）。「减去 / 相交」在闭合时对**当前选中区域的
  `verts` 做多边形裁剪**，结果仍是一个普通多边形区域落盘，引擎无感知。
- **空间维先行**：挖空渲染只看空间，不看 `ranges`；时间轴拖动不改变画布上的覆盖关系
  （与引擎「空间叠加按顺序、时间只在分段处生效」的现状一致）。

## 1. 需求卡（澄清结论摘录）

### 1.1 角色与场景

美术向用户在 360 工作台画 relight 区域，几乎每个 case 都有多个空间上互相重叠的区域
（如天空大区 + 局部亮部），操作心智来自 PS 的选区布尔。

### 1.2 任务与失败路径

主任务：当 A、B 区域重叠时，用户想显式表达「重叠处归 A、B 的生效范围缩小对应的
部分」，以便不查列表顺序就能预测成片参数，并用熟悉的 PS 操作拿到想要的形状。

失败路径。

- 「减去 / 相交」裁剪后顶点数超过 64：拒绝闭合，提示先简化形状或减少裁剪边数
  （沿用 `regionShapeIssue` 的机制报错思路，报具体哪一项超限）。
- 裁剪结果自交或为空（两个区域不相交时做「相交」）：拒绝并保留原 `verts`，提示原因。
- 裁剪涉及盖帽区域或跨接缝的 unwrap 多边形：首版对盖帽直接拒绝布尔运算并提示拆块；
  跨接缝多边形先做 unwrap 后在经度连续域内裁剪，剪完再重新判定 wrap。
- 没有选中区域时按「减去 / 相交」落点：提示先选中一个目标区域。

### 1.3 约束

- 不改 `regions.json` 字段集与引擎合成规则（硬规则 2：冻结契约不扩字段）。
- 球面几何唯一权威点仍在 `vrstudio/frontend/src/utils/erpMath.ts`，裁剪函数加在同一
  文件，不另起投影/裁剪实现。
- 前端不引入新依赖（多边形裁剪自写纯函数，可钉基线测试）。
- 门禁：pytest 与 ruff 全绿、前端 vitest 全绿。

### 1.4 验收（可在浏览器或测试里观察）

- 画 A、B 两个重叠区域（B 在 A 下方），画布重叠处只显示 A 的颜色；B 的可见填充在
  重叠处被 A 盖住，边界处保持现有羽化过渡。
- 调整顺序（B 置顶）后画布重叠处颜色随之变为 B，与引擎参数场归属一致。
- 用「减去」模式从选中区域剪掉一块后：保存、刷新，区域形状为剪后的多边形；小样帧
  区域内外像素符合剪后形状的预期。
- 「相交」模式在两个不相交区域上操作时被拒绝且原区域不变，提示具体原因。
- 多边形裁剪纯函数（并/减/交）有单测：已知形状的裁剪结果、往返恒等式
  （`sub(a, sub(a, b)) == sub(a, b)` 一类）、顶点数上限与自交拒绝分支。
- 排序操作（置顶/上移/下移/置底）保存后刷新，顺序持久。

### 1.5 范围三栏

现在必须做。

- 挖空渲染：按列表顺序自下而上叠色，上层覆盖下层（`ErpRegionViewer.vue` 的 mask
  纹理着色路径）。
- 排序操作：区域列表与选中态的置顶 / 上移 / 下移 / 置底。
- PS 式绘制模式：新选区 / 减去 / 相交三档，工具栏按钮 + 快捷键。
- `erpMath.ts` 多边形裁剪纯函数（subtract / intersect）与非法结果报错。

以后可以做。

- 跨顺序的显式 subtract 区域（契约立项：区域级 `mode` 字段，从所有非 subtract 区域
  里减去，与顺序无关）。触发条件：用户实际提出「B 必须排在 A 下方但形状上要避开 A」
  的用例。
- 重叠区斜纹检查模式（选中区域时标出它被别人覆盖的部分）。
- 挖空渲染随时间轴动态变化（考虑各区域 `ranges` 的出现 / 消失）。
- 盖帽区域参与布尔运算。

明确不做。

- 引擎端任何合成语义改动（加法混合、减法合成规则）；文档 `relight-regions-plan.md`
  §1.5 的「不做加法混合」继续有效。
- PS 的「排除」第四运算（对称差）：当前没有用例，裁剪函数也不为它留分支。
- 布尔运算作用于多个目标区域（「从所有下层区域里减去」）；首版只作用于选中的一个。

### 1.6 优先级

先做挖空渲染 + 排序（WP1），再补布尔绘制模式（WP2）。理由：WP1 小且零风险，
直接兑现「A 独占重叠区」的结果语义，是用户痛点的主体；WP2 是操作习惯层，在 WP1
的顺序语义之上做几何编辑，两者独立验收。

## 2. 现状与根因

- 重叠合成规则（`regions.py build_maps` → `_blend`）已经是「上层独占、羽化过渡」，
  即「B 减去与 A 的重叠」在**结果上已成立**，只取决于列表顺序。
- 画布填充（`ErpRegionViewer.vue` 的 `renderMask` / mask 纹理片元着色）按区域独立
  填色，不体现顺序覆盖，所以用户看不出 B 的实际生效范围已被 A 扣掉。
- 唯一的排序入口是隐性的数组顺序，没有任何显式 UI。
- 文档 `relight-regions-plan.md` §7 把「环带、洞与补集」列为不做，本文不推翻该决策：
  落盘几何仍是单个简单多边形，布尔只发生在编辑瞬间的 `verts` 裁剪上。

## 3. 方案

### 3.1 WP1：挖空渲染与排序

渲染：mask 纹理的生成从「逐区域各画各的」改为「按列表顺序自下而上依次写入，后写的
覆盖先写的」，与引擎 `build_maps` 的遍历顺序同构；羽化边缘的处理保持现状（上层羽化
带向下层过渡，视觉与引擎的 `_blend` 行为一致）。禁用的区域不参与叠色，保持现有的
隐藏表现。

排序：`RegionWorkbench.vue` 区域列表项加四个操作（置顶 / 上移 / 下移 / 置底），
改的是 `regions` 数组顺序并走现有防抖保存；画布选中态的快捷菜单提供同样四项。
顺序就是引擎的合成顺序，不引入额外的 z 字段。

### 3.2 WP2：PS 式绘制模式

工具栏三档：**新选区**（现状）/ **减去**（从选中区域减去）/ **相交**（与选中区域
相交），配快捷键（沿用 PS 心智：新选区无修饰、减去 Alt、相交 Shift+Alt；具体键位
实现时按浏览器冲突再定）。

「减去 / 相交」的绘制流程与现状相同（单击落点、双击闭合）；闭合时：

1. 取选中区域与新画多边形的 `verts`，必要时 unwrap 到同一经度连续域；
2. 调 `erpMath.ts` 新增的裁剪纯函数（`polygonSubtract` / `polygonIntersect`，
   平面域实现，球面细分沿用现有 `densify` 的思路在裁剪前处理大边）；
3. 结果替换选中区域的 `verts`，过 `regionShapeIssue` 校验（顶点数 ≤64、自交、
   盖帽判定）；不合法则拒绝并保留原 `verts`，报具体哪一项超限；
4. 新画的多边形本身不成为区域，也不占用区域数量上限。

首版限制：目标或裁剪形状任一为盖帽（`pole != null` 或 `isPoleCapShape` 为真）时
拒绝布尔运算，提示把盖帽拆成普通多边形再操作。

## 4. 排除的方案

- **引擎/契约层的 subtract 区域模式**（区域带 `mode: "subtract"`，从下层所有区域
  减去，与顺序无关）。排除理由：需要改 `regions.json` 冻结契约、引擎合成顺序与两侧
  测试，成本高；且现有顺序语义已能表达「上层独占」，用户的用例都能靠顺序 + 几何裁剪
  达成。验证方式：WP1/WP2 落地后试用，若出现「B 必须在下但形状要避开 A」的真实用例
  （例如 B 的时间区间需要被 A 盖住同时空间避开），再按「以后可以做」立项。
- **完整 PS 四运算（含排除/对称差）**。排除理由：没有用例，裁剪函数不为它留分支
  （设计原则 1：能删就删）。
- **只做视觉区分（斜纹/描边标记重叠）不改渲染语义**。排除理由：用户明确要「真的
  减法几何」，斜纹只提示「这里有覆盖」仍需用户心算结果；保留为「以后可以做」的检查
  模式。
- **挖空渲染跟随时间轴动态变化**。排除理由：与引擎现状不一致（引擎的空间叠加不随
  时间变化，时间只在分段处生效），做动态会让画布与引擎在小样帧上出现不可对账的分叉；
  成本也高。首版空间维静态。

## 5. 工作包与验收顺序

- WP1 挖空渲染 + 排序：改 `ErpRegionViewer.vue`、`RegionWorkbench.vue`；前端单测
  （叠色顺序、排序持久化）；浏览器验收对照引擎小样帧。
- WP2 裁剪纯函数：`erpMath.ts` 新增 `polygonSubtract` / `polygonIntersect` 与
  unwrap 域裁剪的辅助；vitest 钉基线（已知形状、往返恒等、拒绝分支）。
- WP2 绘制模式：工具栏 + 快捷键 + 闭合时裁剪流程；盖帽拒绝、无选中目标提示；
  浏览器端到端（画 A、减一块、保存刷新、小样对照）。
- 文档：本文批准后按硬规则 6 单独提交；不涉及 `docs/case-model.md`（契约未动）。
