# 重打光区域参数覆盖（relight regions）方案

状态：已批准（2026-11-05），对应决策 88；第一阶段 WP0–WP6 已实施，验收见
`docs/test-runs/20261105-relight-regions.md`，第二阶段（时间区间）待做。前置决策：48（relight 引擎）、
56/59/60（视频重打光与前端一条 flow）、64/65（缓存与报告）、84/85（暗部权重与色度低通）、
82（8K 合成性能）。原型：`.manual-draft/prototypes/relight-regions/`，工作台方案 A 已选定。

## 0. 结论

- **区域是一等对象**：球面多边形 + 逐参数覆盖 + 生效时间，保存进 case，刷新后仍在。
- **首版只做空间与参数**；时间区间是第二阶段，但数据模型从第一版就带 `ranges` 字段，
  首版统一写「整段」，不为第二阶段改结构。
- **覆盖粒度是逐参数**：每个参数各自「默认 / 覆盖」，不是区域一个总开关。
- **可覆盖参数由描述表驱动**：首版三项——整体施加量 `strength`、局部明暗 `local_shading`、
  高光软裁切 `clip.knee` / `clip.max`；以后加参数只改表，不改页面结构。
- **零区域走原路径，逐位一致**；有区域时在 2K 工作尺度上把标量换成逐像素场。
- **前端采用工作台**：360 视图占主位，右侧区域列表与选中区域参数组，默认参数独立成卡，
  时间轴固定在视图下方。

## 1. 需求卡

### 1.1 角色与场景

内部制作与美术在本机工作站的浏览器里使用，单人本地，沿用现有 case 归属与占用锁。
图像重打光是秒级反馈；8K 视频整段一轮约 4.6 分钟（决策 82 的实测），且小样能在正式跑之前
给出几帧结果。区域覆盖通常发生在「整段参数基本对，但某块被氛围图带偏」的时候，一轮里
可能改两三次区域再出片。

### 1.2 任务与失败路径

主任务：当某块画面被氛围图的光照带偏（过亮、过暗、或局部明暗过假）时，我想在 360 视图里
框出它、只给这块单独的施加量与局部明暗，并在出整段前用小样确认，以便其余画面继续沿用
当前默认值，不必为一块区域重调全局参数。

失败路径。

- 顶点少于三个、多边形自交：拒绝闭合，保留已落点并提示。
- 区域跨 ±180° 经线：允许，存不 wrap 的经度；渲染与判定都要正确。
- 区域覆盖极点：首版按「跨度小于半球」的平面判定处理，超出时给出提示并拒绝闭合。
- 区域数量超过上限（首版 16）：拒绝新建，提示先删掉不用的区域。
- 参数越界：前端滑杆夹住，CLI 仍按参数错退出 2，规则只在引擎一处。
- 8K 内存：区域场在 2K 构造，只有当前段放大到原尺寸。
- 没有区域时：报告与成片必须与改动前逐位一致，防止回归。

### 1.3 约束

- 前端 Vue 3 + Element Plus，沿用现有自写 WebGL ERP 观看器，不引入 three.js 一类新依赖。
- 屏幕坐标 ↔ 球面方向的换算只允许有一份实现，新组件不得复制投影数学（硬规则 3 的同一条精神）。
- 视频逐帧流式处理，不整片驻留内存（硬规则 5）；区域场的内存按段释放。
- 几何与编码改动必须 pytest 全绿，含强度 0 与逐位一致基线（硬规则 4）。
- 契约先改 `docs/case-model.md`，再改两侧代码与测试（硬规则 1/2）。
- relight 不调 vrgen、不花额度、不需要项目会话，这一点不变。

### 1.4 验收

以下每条都能在浏览器、日志或测试里观察到。

- 画一个区域、保存、刷新页面，名称、颜色、顶点、参数、时间摘要都还在。
- 转动视角 180° 后，区域仍贴在原来那块画面上；跨经线的区域轮廓连续。
- 区域里只把「整体施加量」设为 0.45、「局部明暗」保持默认时，成片该区域只改施加量。
- 同一区域 `strength = 0` 时，该区域回到 GT 原亮度与原始色温。
- 删除全部区域后重跑，成片与改动前逐位相同。
- 8K 单帧耗时相对无区域路径的增幅记录在报告 `timing` 里，并有上限。
- 区域在视野外时列表仍可选中，选中后视图给出方向提示。

### 1.5 范围三栏

现在必须做。

- 区域对象、球面多边形绘制与顶点编辑、区域列表、逐参数覆盖、保存与回读。
- 参数描述表与三项参数（strength、local_shading、clip）。
- 引擎逐像素参数场、区域软裁切、白平衡混合、零区域逐位一致。
- 小样按区域取帧（`--sample-at`）。
- 报告新增 `regions` 摘要。

以后可以做。

- 时间区间与时间轴交互（第二阶段，见 §5）。
- 区域复制到其他 case、区域模板。
- 逐帧跟踪（机位移动时区域随物体走）。
- 浏览器内近似预览（用 `--dump-light` 的场图在着色器里模拟）。

明确不做。

- 逐帧手画遮罩、逐帧关键帧参数。
- 可编辑的 equirect 主视图（只保留缩略图做全局校对）。
- 区域影响对齐、参考帧、crf 或音频。
- 区域与全局参数的加法混合（语义按列表顺序覆盖，不做叠加）。

### 1.6 优先级

先做空间与参数，再补时间区间。理由：没有区域对象就没有时间维度的作用对象；首版用
「整段生效」就能覆盖大部分需求，且能先验证选区精度与参数场是否正确，再引入时间轴。

## 2. 数据模型

### 2.1 区域对象

存放位置：`cases/<case>/relight/regions.json`（与 `derived/` 同级的新目录），由
`[relight]` 的可选键 `regions = "relight/regions.json"` 指向，缺省表示没有区域。
不用 TOML 内联数组：顶点最多 64 个，数组嵌套在 `case.toml` 里不可读、不可 diff。

```json
{
  "version": 1,
  "regions": [
    {
      "id": "r1",
      "name": "窗边高光",
      "color": "#f59e0b",
      "enabled": true,
      "verts": [[-24.0, 8.0], [-8.0, 11.0], [-4.0, 1.0], [-18.0, -3.0]],
      "feather_deg": 3.0,
      "params": {
        "strength": 0.45,
        "local_shading": null,
        "clip": { "knee": 0.72, "max": 0.98 }
      },
      "ranges": null
    }
  ]
}
```

字段语义。

- `verts` 是 `[lon, lat]`，单位度，经度允许超出 ±180（179 与 181 表示跨接缝的两个点），
  读取方在渲染前归一。纬度限制在 ±89.5°。
- `params` 是稀疏表：`null` 或缺失表示「用默认」。`clip` 存在即表示该区域开软裁切。
- `feather_deg` 是边界羽化宽度（度），按球面距离解释，光栅化时换算到 2K 像素。
- `ranges` 首版为 `null`（整段）；第二阶段为 `[{"start": 8.0, "end": 15.0}, …]`，单位秒。
- `enabled` 只控制这个区域是否参与合成，不等于从列表删除。

### 2.2 参数描述表

前端与 CLI 共用同一份「可覆盖参数」清单，首版三项：

| 参数 id | 显示名 | 类型 | 范围 | 默认来源 | 引擎通道 |
|---|---|---|---|---|---|
| `strength` | 整体施加量 | number | 0–1 | `[relight] strength` 或场景预设 | 增益与白平衡的指数权重 |
| `local_shading` | 局部明暗 | number | 0–1 | `[relight] local_shading` 或场景预设 | 可见度项的指数权重 |
| `clip` | 高光软裁切 | group（`knee` 0.01–0.99、`max` 0.02–1） | — | `[relight] highlight_clip/clip_knee/clip_max` | 合成后的软裁切 |

前端按这份表渲染参数行；新增参数时只加一行描述与一个引擎通道，区域卡、列表摘要与
JSON 校验自动跟上。CLI 侧同一份表用于校验未知键与取值。

**默认参数卡与区域参数卡由同一份表渲染**，这是硬约束而不是约定：默认卡只是少了「默认 /
覆盖」开关，其余控件（滑杆、数值、软裁切的拐点与上限）必须与区域卡完全相同。任何一侧都
不允许手写控件清单——原型第一版就出现过默认卡把高光软裁切写成只读文本、导致「有参数但开
不了」的分叉，正式版用同源渲染从结构上消除这种可能。

### 2.3 覆盖语义

- **逐参数**：区域只覆盖自己声明了的参数，其余继续用默认值。
- **重叠**：按列表顺序，后建的在上面；重叠像素取最上层启用区域的覆盖值。不做加法混合。
- **羽化**：只在区域边界与「下方值」之间过渡；羽化宽度按球面距离换算，边界两侧各一半。
- **时间**（第二阶段）：区间外等于该区域不存在；区间之间不插值，首版不做淡入淡出。

### 2.4 契约变更

- `docs/case-model.md` 的 `[relight]` 段新增可选键 `regions`；`regions.json` 的字段与
  取值按 §2.1 写进契约。
- CLI `vrstudio relight` 新增 `--regions FILE`（可省略），与 `--case` 同时使用时以显式
  文件优先；`--sample-at 12,240,600` 新增，用于按帧号出小样。
- 报告新增 `regions`：`file` 与 `sha256`（这次用的是哪一份区域文件）、数量、启用数、
  是否带区域裁切，以及每个区域的完整定义（`verts`、`params`、`feather_deg`）与像素占比。
  完整定义写进报告是为了事后验收不依赖 `regions.json` 是否被改过；旧字段不动。

## 3. 前端设计

### 3.1 页面结构

`RelightStep.vue` 从「参数面板 + 报告 + 任务」改成工作台，三块：

- **左：360 视图**。GT 当前帧按 `Erp360Compare` 的投影数学渲染，区域以半透明填充 + 轮廓
  叠加；选中区域显示顶点方块。工具条：选择 / 多边形 / 顶点 / 撤销 / 视角复位。拖动转向、
  滚轮缩放（fov 30–120°）。
- **右：侧栏 372px**。区域列表（色块、名称、时间摘要、显隐、删除）、选中区域的参数组、
  默认参数卡（可折叠）。
- **视图下方：时间轴**。第一阶段只显示每行「整段」占位条与播放头；第二阶段补区间拖拽。

### 3.2 组件拆分

- `components/relight/RegionWorkbench.vue`：工作台容器，持有区域状态与保存队列。
- `components/relight/ErpRegionViewer.vue`：视图与叠加层，暴露 `yaw/pitch/fov` 与指针事件。
- `components/relight/RegionList.vue`、`RegionParamGroup.vue`、`RegionTimeline.vue`。
- `constants/relightParams.ts`：可覆盖参数的描述表（唯一来源）。
- `components/relight/ParamRow.vue`：按描述表渲染一行控件，默认卡与区域卡共用；两者都不含
  手写的控件清单，差异只有「是否显示覆盖开关」这一个 prop。
- `utils/erpMath.ts`：屏幕 ↔ 球面、大圆细分、前半球裁切、球面点内判定。**唯一实现**，
  视图、命中测试与缩略图都用它。
- `composables/useRelightRegions.ts`：读写、校验、撤销栈。

### 3.3 选区交互

- **多边形为主**：单击落点，双击或回车闭合；绘制期间从最后一个顶点到鼠标准位置画实时虚线
  （已定）；Esc 取消，Backspace 回退上一个点；顶点可拖动，边上单击加点，右键删点；
  上限 64 个顶点。
- **绘制时拖动画面转向**：左键、中键或右键按住拖动都是转视角，松手没移动才算落点；
  右键在绘制态不弹浏览器菜单、也不删顶点。因为顶点存的是球面坐标，跨视角落点天然成立。
- **选中即编辑，不另开「顶点」模式**：选中区域后直接显示顶点手柄，拖动顶点优先于相机旋转；
  点在区域内侧靠近边线时插点，点在顶点上时删点（至少保留三个）。少一次模式切换，代价是
  顶点附近不能起手转向，用缩放与点空白处转向即可。
- **列表行内操作**：双击名称改名；点色块在预置色板里循环换色；眼睛只控制轮廓显示；
  行尾删除区域（选中态回到第一条）。
- **套索作为快速入口**（后续）：手绘后按距离采样并简化成顶点，仍落成可编辑多边形。
- **精度**：缩到 fov 30° 再落点；另外给一张小 equirect 缩略图叠加轮廓，用于全局与接缝校对。
- **可视角外**：区域顶点在相机后方时按大圆细分后裁到前半球；列表显示方向提示，点击可把
  视角转过去。
- **高亮选区开关**：默认勾选，选区按醒目样式叠加；取消勾选后**不铺中间的颜色**，
  只保留虚线的彩色边与缩小的彩色顶点，名称标签也收起，用于安心看画面。
  开关状态不进 case，每次进入页面恢复默认。

### 3.4 参数与展示

- 每个参数一行：名称、滑杆、数值、「默认 / 覆盖」开关。关闭开关时数值显示默认值并置灰。
- 默认卡与区域卡由同一份参数描述表生成，控件集合永远一致；默认卡没有覆盖开关，区域卡有。
  软裁切在两处都必须是「开关 + 拐点 + 上限」三件套，不允许一处只显示状态。
- 参数组末尾固定一行「＋ 可扩展参数」，列出尚未接入的项，作为可扩展性的占位说明。
- 列表行的摘要显示「整段」或区间（第二阶段），不显示全部参数值，避免侧栏过长。
- 默认参数卡与区域参数卡视觉分开：前者是「未覆盖处」，后者是「这一块」。

## 4. 引擎改动

### 4.1 逐像素参数场

现有公式（决策 84）：

```text
w       = G_low / (G_low + 0.01)
gain    = gY^(strength × w)
vis     = V^(local_shading × strength × w)
Ws      = (1 − strength) × I + strength × W
out_lin = GT_lin × Ws × gain × vis
```

把 `strength` 与 `local_shading` 换成 2K 上的 `s(x, y)`、`l(x, y)`，其余不变：

```text
gain    = gY^(s(x,y) × w)
vis     = V^(l(x,y) × s(x,y) × w)
out_lin = GT_lin × [I + s(x,y) × (W − I)] × gain × vis
```

白平衡按逐像素混合实现：先算 `GT_lin × I` 与 `GT_lin × W` 两个结果再混合，等价于
`(1 − s)I + sW`，但只在有区域时多一次 3×3 乘。`strength = 0` 的区域因此回到原色温，
不会留下全局色偏。

### 4.2 区域光栅化

新增 `src/vrstudio/relight/regions.py`，唯一的区域几何权威点：

- 经度 unwrap 后按 ERP 的线性映射（`x = (lon + 180) / 360 × W`、`y = (90 − lat) / 180 × H`）
  画到 2K 掩码；跨接缝时把多边形平移到 ±W 再画一遍。
- 羽化用距离变换或高斯模糊，宽度按 `feather_deg` 换算。
- 输出每像素的 `s`、`l`、`clip_knee`、`clip_max` 与 `clip_on` 五张场（float32 或 uint8）。
- 这一层只做 lon/lat → ERP 像素的映射，不涉及相机投影，不复制 `patch/projection` 的规则。

### 4.3 分段与缓存

- 第二阶段按「当前生效区域集合」把整段切成若干段；每个集合只构造一次场，帧循环里只查表。
- 段的场在 2K 构造，使用时才放大到原尺寸；切换段时释放上一段的放大结果，峰值内存不随段数增长。
- 没有区域时完全不进这段代码，沿用现有 `light_compose` 与 `apply`。

### 4.4 区域软裁切

`soft_clip` 增加可选的逐像素 `knee` / `max` 数组。像素的裁切参数由最上层启用区域决定；
区域关闭时用全局设置。裁剪仍是同一个公式，因此区域边界只受羽化影响。

### 4.5 小样按区域取帧

新增 `--sample-at`：显式帧号列表优先于 `--sample N`。前端按选中区域的时间区间取起点、
中点、终点三帧（无区间时取全片 25%/50%/75%），解决「均匀采样可能一张都没落在区域内」。

## 5. 工作包

第一阶段：空间与参数。

- **WP0 文档与契约**：本文、`docs/case-model.md`、`decisions.md`；`regions.json` 与
  `--regions` 的字段集先定。
- **WP1 只读叠加**：区域数据读取、列表、视图叠加与选中联动，不可编辑。
- **WP2 选区编辑**：多边形绘制（含实时虚线）、顶点拖动、删除、改名、配色、跨经线。
- **WP3 参数组**：描述表驱动的参数行、默认/覆盖、软裁切、羽化、保存与回读。
- **WP4 引擎**：`regions.py`、逐像素场、区域软裁切、白平衡混合；零区域逐位一致基线。
- **WP5 小样**：`--sample-at` 与前端三帧选取。
- **WP6 验收**：真实 8K 素材一轮完整流程，记录耗时、内存与报告。

第二阶段：时间区间。

- **WP7 数据与引擎分段**：`ranges` 参与分段与场缓存；区间外等于区域不存在。
- **WP8 时间轴**：区间拖拽、增删、播放头联动、列表摘要。
- **WP9 可选淡入淡出**：两端各 0.3 秒的过渡；不做成首版必需。

## 6. 验收

第一阶段。

1. 画区域 → 保存 → 刷新 → 回读一致（名称、颜色、顶点、参数、羽化）。
2. 转动 180° 后区域位置不变；跨 ±180° 经线的轮廓连续。
3. 区域只覆盖 `strength` 时，`local_shading` 仍随默认值变化（改默认，区域内结果跟着变）。
4. 区域 `strength = 0`，该区域与 GT 的逐像素 `maxdiff == 0`（编码往返误差以内）。
5. 删除全部区域后重跑，成片与改动前逐位相同；报告除新增 `regions` 外与旧版同构。
6. `--sample-at` 指定帧号出片，帧号与文件名对应。
7. 8K 单帧耗时相对无区域的增幅记录进报告，且不超过约定上限（实测后填入）。
8. 参数一致性：对描述表里的每一项，默认卡与区域卡渲染出的控件集合完全相同（同一个
   `ParamRow`，单测断言两处控件 id 集合相等）；软裁切在两处都能开关并改拐点与上限。

第二阶段。

8. 区间外帧不套用该区域；区间内逐帧一致；段切换处无跳帧、无内存增长。
9. 时间轴拖拽后重新渲染，生效帧数与列表摘要一致。

## 7. 明确不做

- 逐帧手画与逐帧关键帧参数。
- 可编辑 equirect 主视图。
- 区域影响对齐、参考帧、编码与音频。
- 区域参数与全局参数做加法混合。
- 跨 case 的区域模板与自动跟踪。

## 8. 风险与回退

- **区域几何出错**：所有 lon/lat 与 ERP 像素的换算集中在 `relight/regions.py`，前端集中在
  `utils/erpMath.ts`；两处都有独立单测，出问题时先比对这两处的中间量。
- **8K 内存**：场只在 2K 构造，按段放大与释放；用现有 `timing` 与峰值内存记录验收。
- **逐位基线**：没有区域时不得进入新代码路径；测试用 `strength=0` 与无区域两条基线守住。
- **回退**：删除 `[relight] regions` 键即回到无区域行为；前端区域卡整体隐藏，页面其余部分不变。
