# 重打光区域时间区间（relight regions 第二阶段）方案

状态：审查稿（2026-11-06），待批准后实施；对应决策 91，扩展决策 88 里预留的
`ranges` 字段。前置：决策 88（区域参数覆盖与逐像素场）、89（极点盖帽）、
56/64/82（视频固定光照、缓存与 8K 合成性能）。第一阶段的验收见
`docs/test-runs/20261105-relight-regions.md`，盖帽见
`docs/test-runs/20261105-relight-pole-regions.md`。本方案只动时间维度，不改几何与
参数语义。

## 0. 结论

- `ranges` 从「必须为 null」变成可选区间列表：`null` 表示整段生效，非空表示若干秒区间。
- 一个区域可以有多段。解析端把同一区域的区间排序合并成并集；前端同一条区域轨道不允许
  画出重叠区间，不同区域之间可以在同一时间同时生效。
- 时间 → 帧的换算与分段只在 `relight/timeaxis.py` 一处；区间外帧按「该区域不存在」处理。
- 图片底版不渲染时间轴，也不产生任何区间；图片 case 的 `ranges` 恒为 `null`，引擎对
  遗留的非 null 数据按参数错拒绝，作为手改文件的兜底。
- `--sample N` 保持全片均匀采样；本阶段不接 `--sample-at`，不做淡入淡出。
- 无 `ranges` 的运行与改动前逐位一致；区间外帧与「没有这个区域」的运行逐位一致。

## 1. 需求与边界

### 1.1 场景

氛围依据只在一段时间内与 GT 对得上：片头灯没亮、片尾转场、人物中途进出画面。用户希望
空间区域已经画好的参数只在某几段生效，其余时间整段沿用默认值，不必为同一块区域复制
多份、也不需要在时间上重调全局参数。

### 1.2 失败路径

以下每条都按参数错退出 2，并说明是哪一条数据不合约：

- 区间不是对象、`start`/`end` 不是有限数字（布尔值也不接受）、`start < 0`、`end <= start`。
- `ranges` 是空数组：等于「这个区域从不生效」，与 `enabled = false` 重复；语义只留一处，
  空数组按参数错拒绝。要表达不生效请用 `enabled`。
- 单个区域原始区间超过 64 条，或并集后超过 8 段。
- 整条时间轴按生效集合切出的段数（含没有区域生效的空隙）超过 128 段。
- GT 是视频但帧率未知（`fps <= 0`），且至少一个启用区域带非空 `ranges`：无法把秒换算成帧。
- GT 是图片，且至少一个启用区域带非空 `ranges`：图片没有时间维度，见 §2.4。
- 区间终点超过片长：不报错，引擎夹到最后一帧；夹完为空则该区间不生效。
- 区间起点超过片长：不报错，该区域全程不参与合成，报告里 `active_frames = 0`。

### 1.3 约束

- 唯一权威点：时间 → 帧与分段只住 `relight/timeaxis.py`；`regions.py` 只负责结构与
  并集校验；前端不复制并集算法，也不复制帧换算（硬规则 3 的同一条精神）。
- 视频仍逐帧流式处理；段切换只换区域场，不重解码已经过去的帧。
- 任一时刻只保留当前段的 2K 区域场、放大后的 `LightCompose` 与裁切场；切换前先释放
  上一段，峰值不随段数增长。
- 无 `ranges` 时不进分段逻辑，仍走现在的单段构造，成片逐位一致。

### 1.4 验收总览

浏览器、日志与报告三处都能观察到：

- 画好区域、在第 8–15 秒与第 22–30 秒各拖一段、保存刷新后两段仍在。
- 只有这两段里的帧套用该区域，其余帧与「删掉这个区域」的运行逐位相同。
- 同一区域两条区间在轨道上拖到相接时合成一段，拖不过相邻区间；不同区域的时间可以重叠。
- 图片底版看不到时间轴；把底版从视频换成图片后，遗留区间被清除并提示一次。
- 报告里能只凭报告本身复现每个区域的区间、每段的生效集合与生效帧数。

## 2. 数据模型与契约

### 2.1 `ranges` 字段

```json
{
  "id": "r1",
  "ranges": [{ "start": 8.0, "end": 15.0 }, { "start": 22.5, "end": 30.0 }]
}
```

- 缺省或 `null`：整段生效，与第一阶段完全一致。
- 非空数组：区间列表，单位秒，`0 <= start < end`；`start`、`end` 是有限数字。
- 只认 `start`、`end` 两个键；未知键按参数错拒绝，与区域其余字段的校验风格一致。
- 数组顺序不承载语义；解析后按 `start` 升序，并在内存里保存为规范形式。
- `enabled = false` 的区域保留 `ranges`，但不参与分段与合成；重新启用后区间照旧。

### 2.2 并集规范化

解析时对同一区域的 `ranges` 做一次并集：

1. 按 `start` 升序排序。
2. 若下一条的 `start <= 上一条的 end + 1e-9`，合并成 `[start, max(end)]`。
3. 合并后仍超过 8 段按参数错拒绝。

相接（`next.start == current.end`）算合并，因为两段在时间上连续、分开不会产生任何
不同的结果。规范化在解析时完成，不改写用户手写的文件；Web 读写接口都按同一结果返回或
落盘（§6），所以页面看到的永远是并集结果。

### 2.3 校验与上限

- `MAX_RANGES_RAW = 64`：解析前单区域最多 64 条，防止病态文件把并集排序拖慢。
- `MAX_RANGES_PER_REGION = 8`：并集后单区域最多 8 段。
- `MAX_SEGMENTS = 128`：整条时间轴上生效集合发生变化的分段总数上限，空隙也计入。
- 上限只放在解析与分段两处，CLI、Web 与前端不各写一份。

### 2.4 图片底版

图片 GT 没有时间维度，这一条从界面到引擎共四层：

- **前端**：`payload.media === 'image'` 时不渲染时间轴模块；区域列表的摘要显示「整段」。
- **保存**：前端与 Web 保存接口在底版是图片时，把所有区域的 `ranges` 一律写 `null`。
  载入时若发现遗留的非空区间（例如底版从视频换成了图片），页面提示一次「底版是图片，
  已清除 N 个区域的时间区间」并立即按 `null` 落盘，不等用户再编辑。
- **运行**：`vrstudio relight` 不新增任何区间参数，web 的 `relight` op 也不新增区间字段；
  图片底版的 argv 与今天完全相同，区间没有入口可传。
- **引擎兜底**：`load_regions` 之后若底版是图片且任一启用区域 `ranges` 非空，按参数错
  退出 2，提示「图片底版没有时间维度：删掉 ranges 或改用视频底版」。这一条只拦手改文件
  或绕过前端的调用，正常使用不会撞到。

这样界面层完全避开问题，文件层也不会留下「图片 case 带着区间」的中间状态；兜底只是防止
有人直接改 JSON。

### 2.5 `Region` 与报告

`Region` 增加 `ranges: tuple[TimeRange, ...] | None`，`TimeRange` 是 `start`/`end` 两个
`float` 的冻结数据类。只有 `None` 表示整段；空元组不表示任何语义，解析阶段直接拒绝，
因此引擎里不会出现「有这个字段但一段都没有」的第三种状态。

报告 `regions` 段新增：

- 每个区域：`ranges`（规范形式，整段写 `null`）与 `active_frames`（该区域真正参与的帧数；
  帧数未知时写 `null`）。
- 顶层 `segments`：按时间顺序列出每一段，`{"start": 帧号, "end": 帧号, "regions": [id…]}`；
  没有区域生效的空隙写空数组。报告自带这一段，事后验收不必再跑一遍 CLI。
- `timing` 增加 `region_build`（构造各段区域场与放大场的累计秒数）与 `region_switches`
  （段切换次数）。旧字段一个不动。

`coverage` 仍表示空间像素占比；一个区域在多段里出现时取任一段的覆盖率（空间占比与时间
无关），从未生效时为 0。

## 3. 时间 → 帧与分段（唯一权威点）

新增 `src/vrstudio/relight/timeaxis.py`，只做两件事：把秒区间换算成帧区间，把各区域的
帧区间切成「生效集合不变」的段。`regions.py` 不出现帧号，`cli/relight.py` 不出现换算公式。

### 3.1 帧时刻用微秒整数比较

浮点比较会在边界上错一帧，而且前端把秒保留 6 位小数后，`71/30 = 2.366667` 两边的舍入
方向还可能不一致。统一换成微秒整数：

```text
frame_us(i) = round(i / fps × 1_000_000)
start_us    = round(start × 1_000_000)
end_us      = round(end × 1_000_000)
帧 i 生效  ⇔  start_us <= frame_us(i) < end_us
```

左闭右开：`end` 那一帧不属于区间，相邻两段因此既不重叠也不漏帧。例如 10 fps 下
`[0.2, 0.5]` 命中第 2、3、4 帧，第 5 帧属于下一段或空隙。

段边界先按 `floor(start_us × fps / 1e6)` 估一个起点，再用同一判定向两侧修正最多一帧；
不在段构造里逐帧扫描整条视频。

### 3.2 分段

1. 只取 `enabled = true` 且 `ranges` 非空的区域；`ranges = null` 的区域覆盖整条时间轴。
2. 收集所有区域帧区间的端点，排序去重。
3. 每两个相邻端点之间是一个候选段，生效集合 = 覆盖这一段的区域 id 集合。
4. 生效集合相同的相邻段合并（规范化后通常只出现在空隙两侧）；空隙也是一段，集合为空。
5. 分段总数超过 `MAX_SEGMENTS` 按参数错拒绝。

所有区域都没有 `ranges` 时只有一段，集合为全部启用区域，构造顺序与今天的
`_region_maps` 完全一致。区域在某个段里不生效时，构造该段的 `build_maps` 只传入这一段
的启用区域，因此叠加顺序仍是原数组顺序，区间外等价于该区域不存在。

### 3.3 未知帧率与帧数

- `fps <= 0` 且至少一个启用区域带非空 `ranges`：参数错，提示去掉区间或换 ffprobe 能
  报告帧率的文件。没有区间时照旧运行，`--sample` 的取帧回退逻辑不受影响。
- `frames` 未知（ffprobe 不报告帧数）：不做终点夹取；超出所有区间端点的帧按空隙处理，
  仍走标量路径。小样的帧号校验只在帧数已知时做。

### 3.4 模块接口

```text
FrameRange(start: int, end: int)                 # 半开区间
Segment(start: int, end: int, regions: frozenset[str])

frame_ranges(ranges, fps, frames=None) -> list[FrameRange]
segments(region_list, fps, frames=None) -> list[Segment]
segment_at(segments, index) -> Segment | None   # 二分；落在所有段之外返回 None
```

`segments` 只依赖区域与帧率，不依赖分辨率与段数以外的运行参数；构造一次，整段复用。

## 4. 引擎改动

改动集中在 `cli/relight.py`；`compose.py`、`fields.py`、`align.py` 不改。

### 4.1 三条路径与小样

- **图片 GT**：在 `relight()` 分派处检查 `ranges`，非空按参数错退出；之后路径不变。
- **视频 GT + 图片氛围**（`_relight_video`）：现在一次构造 `maps`、`light`、`clip_full`，
  整段复用。改成 `SegmentCache`：按当前帧号取段，段变化时重建这一组；段落只保留当前段。
- **视频 GT + 视频氛围**（`_relight_video_atmo`）：光场本来就逐帧估，区域场按段取；
  `_compose_light(fields, size, params, maps)` 与 `_apply_clip` 的签名不变，只是 `maps`
  与裁切场来自当前段。
- **小样**（`_write_samples` / `_write_samples_pair`）：帧号表已排序，按同一个 `SegmentCache`
  取段；采样点跨段时重建，最多切换采样点数次。

### 4.2 `SegmentCache` 的生命周期

- 键是段下标；只在段变化时构造：`build_maps`（2K）→ `light_compose`（放大到输出尺寸）
  → `upscale_clip`（有区域裁切时）。
- 构造新段之前先释放上一段的 `LightCompose` 与裁切场。两者都是全尺寸 float32 数组
  （8K 下 `LightCompose` 约 350 MB、裁切两张约 236 MB），先放后建可避免瞬时翻倍。
- 同一生效集合在不同时间段重复出现时仍重建，不按集合缓存：缓存 2K 场省不下多少时间，
  缓存全尺寸场会重新引入内存随段数增长的问题。
- 没有 `ranges` 时只有一段，构造一次，调用顺序与今天相同，不引入额外拷贝。

### 4.3 零段与零强度捷径

- 某段没有生效区域：`maps = None`，`_compose_light` 退回标量路径，与无区域运行一致。
- 视频氛围路径的 `strength == 0` 捷径按段判断：该段没有区域或区域场强度全为 0 时直接
  返回 GT 副本，沿用现在的 `maps is None or not maps.strength.any()`。
- `_apply_clip`：当前段没有区域裁切时退回全局 `--highlight-clip`，与现在相同。

### 4.4 日志与报告

- 启动行追加 `time: N segments`；段数超过 16 时补一行 warn，说明构造开销会上升。
- 每个启用区域补一行 `ranges: frames a-b, c-d`（整段写 `whole`），便于从日志核对。
- 报告按 §2.5 增加 `segments`、每区域 `ranges`/`active_frames` 与 `timing.region_build`。

### 4.5 性能预期

按 8K、378 帧、每段构造约 0.4–0.5 秒估算：3 段约多 1 秒，16 段约多 7 秒，相对现有
276 秒整段是几十个百分点的零头；128 段上限用于挡住病态输入，不作为可用配置推荐。
视频氛围路径的逐帧光场与段无关，切换只换 2K 区域场与裁切场，开销更小。实际数字写进
验收记录，不预先承诺。

### 4.6 不改的部分

- 对齐、参考帧、固定光照缓存（`relight/cache.py`）与氛围映射都不看时间区间。
- 软裁切公式、色度低通、白平衡逐像素混合与编码参数不变。
- 音频、产物命名、`[relight] current` 回写不变。

## 5. 前端设计

### 5.1 数据来源

`/api/case` 的 `relight.gt` 增加媒体元数据 `meta = {width, height, duration, fps}`，由
`_slot_payload` 调现有的 `_media_meta`（按路径 + mtime + 大小缓存，视频只读容器元数据）。
前端类型 `RelightSlot.meta` 可选；取不到时 `duration`/`fps` 为 `null`。

- `duration` 缺失：时间轴整体禁用并提示「读不到片长，暂不能编辑时间区间」。
- `fps` 缺失：时间轴只读（已有区间照常显示），提示「读不到帧率，无法把秒换算成帧」。
  避免用户编完再被引擎拒绝。

播放头与视图联动：`ErpRegionViewer` 已经通过 `time` 事件给出当前时间并暴露 `seek()`；
`RegionWorkbench` 接住这两个口，时间轴点哪里、视图就跳哪里，播放时播放头跟着走。

### 5.2 `RegionTimeline.vue`

新增 `components/relight/RegionTimeline.vue`，只负责时间轴与区间条的绘制和指针交互，
不读写文件、不做并集：

- props：`regions`、`selectedId`、`duration`、`fps`、`playhead`、`readonly`。
- emits：`update`（区域 id、新的 `ranges`）、`select`、`seek`。
- 一行一个区域，条的颜色取区域颜色；选中行加亮；行首是名称与区间摘要。
- 刻度尺显示分秒；播放头一条竖线，可点击拖动。

### 5.3 交互规则

- **空白双击新建**：在该位置新建 1 秒区间（片长不足 1 秒时取整段），自动选中该区域。
- **拖动条身平移**，**拖动两端改起止**；都可点击。
- **吸附到帧**：拖动结果按 `round(t × fps) / fps` 落到帧边界，保存时秒保留 6 位小数；
  `fps` 缺失时不吸附（该模式本来就只读）。
- **同一区域不重叠**：拖动被夹在相邻区间之间，最短 1 帧；拖到与相邻区间相接时立即合并
  （只处理这两条相接的条，不做任意重叠的并集），与引擎的并集规则一致，保存前后看到的
  形状相同。
- **不同区域允许重叠**：每个区域是独立的一行，时间上可以同时生效；叠加顺序仍按区域
  数组顺序，与空间重叠的规则一致。
- **删除**：右键时间轴上的条删除该段；区域列表行尾的按钮仍删除整个区域，两者不混用。
  删掉最后一段后 `ranges` 变回 `null`（整段），不是空数组。
- **上限**：单区域最多 8 段，达到上限后新建按钮禁用并提示先删一段。
- **范围**：条始终夹在 `[0, duration]`；拖动不越界。
- 本阶段不做时间轴缩放、多选、跨区域复制区间；长片上的短区间精度有限，记入「以后可做」。

### 5.4 列表摘要

区域列表行的时间摘要按规范区间生成：

- `null`：「整段」。
- 一段：`0:08–0:15`。
- 多段：`3 段 · 0:08–0:15 等`，悬浮显示全部区间。

摘要只做显示，不做并集；输入永远是 Web 读接口给的规范形式。

### 5.5 图片底版

- 不渲染 `RegionTimeline.vue`，列表摘要固定「整段」。
- 载入时若有非空区间：提示一次并立即把全部 `ranges` 置 `null`、走现有防抖保存落盘。
- 保存函数在 `media === 'image'` 时无条件写 `null`，防止后续编辑再带出区间。
- 运行请求与今天完全相同，不新增任何区间字段。

### 5.6 保存

`RegionWorkbench` 的保存快照现在是 `{ ...region, ranges: null }`（第 120 行），改成

## 6. Web 接口

- `GET /api/case/{name}/relight/regions` 返回规范形式：解析成 `Region` 后，按下标把每个
  区域的 `ranges` 换成并集结果（`[[start, end], …]` 或 `null`），其余字段原样返回；不重建
  整份文档。前端因此永远不需要实现并集；手改文件里的重叠区间也会以合并后的形状出现。
- `POST` 仍按整份 JSON 校验后落盘，落盘前用同一个按下标替换 `ranges` 的小函数规范化；
  GET 与 POST 共用这一处。底版是图片时，落盘前把 `ranges` 一律置 `null`，不新增错误路径。
  其余字段不改写，也不新增序列化器。
- `/api/case` 的 `relight.gt.meta` 按 §5.1 增加，`atmo` 同样带 meta（以后做预览时可用）。
- `relight` run op 的 argv 不变：没有 `--ranges` 一类参数，区间只经 `regions.json` 进入
  引擎；`--sample-at` 仍只在 CLI 可用，本阶段不接前端。
- 现有 400 错误路径不变：坏 JSON、未知键、区间不合约都返回具体原因。

## 8. 验收

单测与静态门禁（`uv run pytest`、`uv run ruff check .`、前端 `typecheck`/`lint`/`test`/`build`）。

- 解析：整段/单段/多段/并集/相接合并；空数组、倒置、负数、布尔、未知键、原始条数与
  并集段数超限都按参数错报出具体原因。
- 帧换算：10 fps 下 `[0.2, 0.5]` → 第 2、3、4 帧；`[0.2, 0.3]` → 只有第 2 帧；
  `end` 正好落在帧时刻时该帧不属于区间；29.97 fps 的边界不漂移；越界终点夹到片尾。
- 分段：两区域时间重叠时同一段里同时生效；中间有空隙时空隙段集合为空；段数超 128 报错。
- 逐位基线（crf 0，`--set video.preset=ultrafast`）：
  - 区域存在但 `ranges` 全为 `null` 的成片与改动前 SHA256 相同。
  - 区间外帧与「删掉该区域」的运行逐像素 `maxdiff == 0`。
  - 区间内帧与该区域整段生效时同一帧逐像素一致。
  - 边界帧只属于一侧，成片帧数与输入相同，段切换处不重帧、不掉帧。
- 报告：每个区域有 `ranges` 与 `active_frames`；`segments` 与生效集合一致；
  `timing.region_build`/`region_switches` 存在且非负。
- 图片：前端不出现时间轴；CLI 对图片 + 非空 `ranges` 退出 2，提示指向删区间或换视频底版；
  图片模式保存后文件里所有 `ranges` 都是 `null`。
- 浏览器：画两块区域，各拖两段；把同区域两段拖到相接立即合并；尝试拖过相邻区间被夹住；
  不同区域在时间上重叠仍可保存；刷新后区间、摘要与播放头位置正确；播放头与视图双向联动。
- 8K 实测：378 帧整段、3 个区域共 6 段，记录总耗时、`region_build`/`region_switches`、
  峰值内存；峰值不超过「无区间运行」的峰值加一个段的放大场（约 0.6 GB），且不随段数增长。

## 9. 风险与回退

- **边界错一帧**：所有帧号只由 `timeaxis.py` 的微秒规则产生，测试用固定帧率表逐帧断言；
  前端只做显示与吸附，不参与语义判定。
- **段数过多拖慢整段**：上限 128，超过 16 段在日志里 warn；报告中单独记 `region_build`，
  方便定位是区域构造还是解码/合成变慢。
- **内存随段数增长**：`SegmentCache` 只留当前段，先释放再构造；验收记录峰值，不用估算
  代替实测。
- **前端与引擎对并集理解不一致**：前端不做并集，Web 读接口返回规范形式；前端只负责
  不画出重叠。
- **换底版留下区间**：图片模式载入即清除并落盘，引擎再兜底拒绝；两层都只对图片生效，
  视频 case 不受影响。
- **回退**：把所有区域的 `ranges` 改回 `null`（或删掉这个键）即回到当前单段路径；
  前端隐藏 `RegionTimeline.vue` 不影响其余页面。无需回滚数据格式，`version` 保持 1。

## 10. 明确不做

- 淡入淡出、区间两端过渡（原 WP9 不做进本阶段）。
- 逐帧关键帧、逐帧掩码与区域随物体跟踪。
- 前端接 `--sample-at` 或按区间自动取小样帧；`--sample N` 仍是全片均匀。
- 时间轴缩放、多选、跨区域复制区间、区间模板。
- 图片底版的时间轴；图片 case 不保留任何区间。
