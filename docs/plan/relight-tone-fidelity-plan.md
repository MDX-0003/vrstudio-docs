# 重打光强度区间与色彩保真计划

## 1. 问题

`RL_video_02` 用 `v8` 氛围视频、`strength = 0.9` 的成片有三个互相关联的问题：

- 暗部整体发灰、出现成片状噪声与彩斑，看起来像"过曝"；
- 细节处的红带、铃铛、金饰边缘有肉眼可见的锯齿与彩边；
- 成片在播放器里放大后锯齿更明显。

用户的要求是：`strength` 开放 0–1 就必须全区间可用，不能把真实可用区间压到 0.3 以下；
同时改进不能靠牺牲重打光效果换取。

## 2. 定位与实测

### 2.1 锯齿不在光场里

- 光场在 2K 估计、线性放大到 8K，`gain` 与 `visibility` 在 8K 上的 Laplacian 方差都是 0.00。
- 把 2K 光场用 σ=32（8K 上约 128 px）模糊后重新合成，钟磬区 Laplacian 方差 176→172，
  与当前输出的差异 mean 1.17/255、p99 9，台阶位置逐像素不变。
- 结论：乘算光场只改亮度，不产生也不移动边缘；"在打光计算里平滑"对锯齿无效。

### 2.2 锯齿在 GT 的像素里，被对比与色度放大

- GT 是原生 8192×4096（缩到 4K 再放回 8K 的往返 PSNR 只有 44.69 dB；氛围图同测 51.17 dB，
  说明氛围图的 8K 是 4K 上采样，GT 不是）。
- 8K 的钟磬、红带在场景尺度上只有几十像素宽，边缘本身就是 1–2 px 的台阶；
  GT 自己编码留下的 8×8 块噪声在红带上清晰可辨。
- 同一 150×120 裁剪的边缘能量（Laplacian RMS，24 帧平均）：
  亮度 9.84 → 重打光后 13.38（+36%），Cb 7.64 → 10.66，Cr 3.80 → 5.89（+55%）。
- 4:2:0 的色度只有半分辨率，红带与黑背景的色度边界本来就是 2 px 一档；色度对比再抬
  55%，彩色台阶就比 GT 明显得多。

### 2.3 暗部增益是过曝的主因

- GT 线性亮度 < 0.002 的像素占 26%，< 0.01 的占 71%。
- 这一段的 `gain = low(atmo)/low(GT)` 均值 4.3–4.9、p95 12–13、最大 149。
- 旧公式在 0.9 下把黑场抬高 2.6 倍（Y 3.7→9.5、饱和 7.5→16.5），整帧 Laplacian 方差
  25.4→72.5、饱和 26.7→42.5、≥250 像素 0.003%→0.20%。
- 结论：`strength` 的问题不是"太大"，而是比值在近黑处没有意义。

### 2.4 编码与观看端的附加损失

- 24 帧同一序列、四种编码设置的边缘能量（亮度）：GT 9.84，编码前 13.38，
  crf 18 veryfast 12.69（相对编码前 −5.2%），crf 18 slow 13.00（−2.9%），
  crf 14 slow 13.18（−1.5%），crf 10 slow 13.35（−0.3%）。
- 4K 预览（crf 22、2.9 Mbps）在同一区域的亮度边缘能量只有 4.9，是 GT 的 42%。
- 结论：编码只占相对 GT 那 +36% 增幅里的约 5 个百分点，提高编码质量让台阶更清楚而不是更少；
  4K 预览不能用来判断细节。

### 2.5 色彩标签

- 旧产物四个色彩标签全是 unknown：swscale 默认按 BT.601 转 YUV，而播放端对无标签的
  HD/8K 流按 BT.709 解释，同一文件两种矩阵解码每通道均值差 1.7、p99 9 个码值。

## 3. 改动

### 3.1 暗部置信权重（决策 84）

```text
w      = G_low / (G_low + 0.01)          # G_low = max(luma(gt_light), 0)，线性光，2K
gain'  = gain ^ (strength × w)
vis'   = visibility ^ (local_shading × strength × w)
Ws     = (1 - strength) I + strength W    # 不变
```

`SHADOW_PIVOT = 0.01`（线性光，约 sRGB 28/255）是 8-bit 素材还能承载反射率的量级，
低于它的位置不让乘算场进入。固定常量，不开参数。`strength = 0` 时指数为 0，
输出仍与 GT 逐位一致；两个场在 2K 上求幂，再放大到原尺寸，与原实现的放大顺序不同，
但仍是同一份场。

### 3.2 色度差低通（决策 85）

```text
d        = relit - GT                    # 8-bit BGR，原分辨率
y        = 0.114 d_B + 0.587 d_G + 0.299 d_R
chroma   = d - y
out      = relit + (blur(chroma, σ=2) - chroma)
```

亮度分量逐位不动，只把"额外加上去的色度对比"磨平。`CHROMA_SIGMA = 2.0`，固定常量。
实现按行带分线程，带外留 8 行（大于 σ=2 对应核半径 6），整帧与行带 `maxdiff == 0`。

### 3.3 交付编码统一 BT.709（决策 86）

`FrameWriter` 的编码参数增加：

```text
-vf scale=in_range=full:out_range=tv:out_color_matrix=bt709
-colorspace bt709 -color_primaries bt709 -color_trc bt709 -color_range tv
-x264-params colorprim=bt709:transfer=bt709:colormatrix=bt709
```

对 relight、recompose、merge、patch 的全部视频产物生效。

## 4. 效果（`RL_video_02`，`v8`，strength 0.9，第 189 帧）

按区域（0–255）：

- 黑场（占 26.6%）：GT 3.7 / 饱和 7.5 → 旧 9.5 / 16.5 → 新 3.7 / 7.5
- 中间调（占 27.1%）：GT 35.5 / 55.8 → 旧 47.3 / 82.0 → 新 40.4 / 71.5
- 高光（占 0.7%）：GT 141.3 / 109.6 → 旧 151.6 / 151.3 → 新 149.4 / 149.7

钟磬区边缘能量（亮度 / Cb / Cr）：GT 10.82 / 7.63 / 4.01 → 旧 14.35 / 10.41 / 5.99
→ 新 14.28 / 8.96 / 5.14。亮度重打光保持，色度边缘回到 GT 附近。

## 5. 性能

色度低通是新增的全帧浮点步骤，必须不拖慢整段渲染：

- 整帧实现 1.06 秒/帧；行带 + 16 线程 0.23 秒/帧，`maxdiff == 0`（workers = 1/4/16 都验证）。
- 行带每线程只持有自己那一段的临时数组（8K、16 带时每带约 13 MB/数组），
  峰值不随线程数线性上涨；一帧 compose + 色度低通的实测峰值工作集在 0.7 GB 量级。
- 整段 378 帧的原型：只用暗部权重时 271 秒；加色度低通（整帧、串行）时 705 秒，
  其中色度步骤 431 秒。改成行带多线程后色度步骤约 87 秒，预计整段回到 360 秒左右。

## 7. 验收

- `uv run pytest` 全绿、`uv run ruff check .` 干净。
- `strength = 0` 的图片与视频路径仍与 GT 逐位一致（视频以编码往返噪声为界）。
- 色度低通行带实现与整帧实现 `maxdiff == 0`，串行与并行 `maxdiff == 0`。
- `RL_video_02` 整段复跑：黑场与 GT 一致、中间调与高光保持重打光、色度边缘回到 GT 附近；
  整段耗时不超过改动前的 1.5 倍。
- 产物 `ffprobe` 四个色彩标签均为 bt709 / tv。

## 8. 不做的事

- 不继续平滑光场：已实测无效。
- 不对 GT 去块、锐化或超分：与决策 48「GT 提供结构与细节」的定位冲突，会引入白边，
  也不能在没有信息的地方补出细节。
- 不为锯齿新增 `--deblock` / `--denoise` 之类开关：单 case 的口子会把维护成本摊到所有流程。
- 不把色度 σ 做成参数：它由 4:2:0 的色度采样率决定，不是创作选择。

## 9. 已知限制

- 源片 1–2 px 的台阶在 8K 上仍然存在；放大观看时可见，这是交付分辨率的极限。
- 色度低通会让边缘处有极小范围的色彩渗色（σ=2 像素，8K 上不可见；平均改动 0.43/255）。
- 4K 预览（crf 22）比交付档软，不能用于细节判断。

## 10. 实施结果（2026-11-05）
