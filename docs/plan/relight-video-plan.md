# 视频重打光（relight-video）最小方案

状态：已实施（决策 56 的展开）。图像版 `vrstudio relight` 已实施，验收见 `docs/test-runs/20261030-relight-cli.md`；
视频版的实施与验收见 `docs/test-runs/20261030-relight-video.md`（含与本文的差异）。
本轮只做 CLI：用「当前图打光」同一套 v2 引擎，把一张氛围图的光照搬到一段真 GT 视频上。
case / web 接入与固定机位之外的场景都不在本轮。
后续优化见 `docs/plan/relight-decode-cache-plan.md`（决策 64：删除同位检查、单遍取参考帧、
按输入缓存参考帧与相似变换）。

## 1. 需求与边界

- 进：一段 2:1 ERP 的真 GT 视频 + 一张与视频同尺寸（同宽同高）的 AI 氛围图；出：与 GT 同分辨率、同帧数、同帧率的重打光视频。
- 仍是「光照搬运」：GT 每帧提供结构与细节，氛围图只提供低频光照、色温与遮挡；不做超分，不做内容回填，不补帧。
- 氛围图只有一张，所以**对齐与光照场只估计一次，整段复用**。这条决定了适用范围：只对固定机位、光照不随时间变化的镜头成立（360 室内静止机位是主场景）。

## 2. 流程

```text
probe 视频 → 读第 N 帧作对齐参考帧 → estimate_similarity(参考帧, 氛围图)
  → 可信度闸门（< 0.15 退出 1，不出片）
  → warp_to_gt(氛围图, 变换) 一次 → estimate_fields(参考帧, 对齐后氛围图)
  → 逐帧：compose.relight(frame, fields, strength, local_shading) [→ 可选 soft_clip]
  → FrameWriter 编码（H.264 8-bit yuv420p，音频第二遍 -c copy 从 GT 视频带过来）
  → 写报告 JSON（--report 可选）
```

逐帧只做「乘光场」这一件事，对齐与引导滤波都在进帧之前做完。每帧算力与图像版相同（8K 单帧约 4–5 秒），整段耗时随帧数线性增长。

**复用而不重估的理由。** 图像版每张图各估一次变换。视频逐帧重估会让相邻帧的缩放与旋转各跳一点（实测同一素材不同候选之间旋转 −0.14° 到 −0.33°、缩放 0.995–1.015），光照场跟着抖，播放时表现为明暗低频闪烁；而且每帧一次 SIFT 代价接近单帧打光本身。固定一次估计恰好也把「相机没动」这个前提变成显式条件。

**同位检查（实施时替换了方案里的「逐帧跟踪位移」）。** 变换定下来后，把其余帧与参考帧**按同一坐标**比结构重合度（带通后的归一化相关），不需要先估出位移；全段最低值低于 0.94 就警告「画面在动」。理由是相位相关在这种 2K 带通图像上测不准小位移：合成素材单帧平移 4 像素只测出 0.5–0.7 像素，多帧复合后漂移更大，而判据本来只需要知道「还在不在同一坐标」。实测对应关系：同坐标 1.0、平移 4 像素 0.99、16 像素 0.887、40 像素 0.798；真实 8K 固定机位素材 19 帧最低 0.976。

## 3. 参考帧

- `--ref-frame N`（0 起，缺省自动选）：拿哪一帧去和氛围图对齐、去估光照场。

- 缺省时扫整段前 90 帧，在 2K 上取与氛围图结构最相关的一帧；标准差低于 12 的黑场与空镜直接跳过。
- 显式 `--ref-frame` 越界是参数错。选帧时的「与氛围图结构重合度」只做提示、不做闸门：那是**未对齐**的带通相关，几像素平移就能把它压到 0（实测拼接产物有 −9 px 位移，相关从 0.55 掉到 −0.01），而对齐之后本来对得上。真正的闸门只有一条——对齐后的 `correlation_after` 低于 0.15 就退出 1，与决策 48 一致。
- 该帧在视频里同样被重新打光，不从 GT 拷贝。

**已知限制（接受，不在本轮解决）：**

- GT 里有运动物体时，参考帧的物体位置决定可见度项落在哪里，其余帧的物体可能不在该阴影/高光下。固定机位、GT 的静态结构远多于运动物体时影响有限；机位移动则整条不成立，必须逐帧重估加时间平滑，单独立项。
- 依据固定变换，光照不会随时间变化。真实的闪光、火光变化传不过来。

**决策 64 的修正（2026-11-02）。** 重打光素材都是固定机位，原先“其余帧与参考帧按同一坐标比结构重合度、低于 0.94 警告”的整片同位检查已删除；它只警告不阻断，却要额外读一遍全片。报告同时去掉 `frames_checked`/`min_hold`。机位移动只作为适用范围约束，不再运行时检测。

## 4. 输入校验与退出码

| 码 | 条件 |
|---|---|
| 0 | 成功，写出视频（有 `--report` 时同时写报告） |
| 2 | 参数错：GT 视频不是 2:1 ERP、宽高不是偶数（yuv420p 要求）、氛围图与视频尺寸不一致、strength/local-shading 越界、未知场景、`0 < knee < max <= 1` 不成立、`--ref-frame` 为负或越界、`--crf` 越界、配置错误 |
| 1 | 运行失败：探测失败、参考帧不可用（黑场等）、对齐不可信、读图失败、编解码失败、写报告失败 |

与图像版一致：对齐不可信必须中断且不留下半成品。对齐与光照场都在封帧管之前算完，闸门失败时根本没有开始编码；编码途中的失败由命令自己删掉输出文件。不提供「忽略对齐失败」的开关。机位移动只警告、不中断：错误已经发生，中断只会让人看不出错在哪里。

**尺寸对齐。** 氛围图必须与视频的宽高逐像素一致，不做缩放。理由与图像版相同：warp 只做一次，尺寸来源只有一个，缩放应当在上游（生成或 merge）完成，不在打光这一步偷偷插值。

## 5. CLI 契约

```text
vrstudio relight-video --gt GT.mp4 --atmo ATMO.png --out OUT.mp4
  [--ref-frame 0]
  [--scene night|day] [--strength 0..1] [--local-shading 0..1]
  [--highlight-clip] [--clip-knee 0.72] [--clip-max 0.98]
  [--crf 0..51]
  [--report report.json]
  [--config TOML] [--set key=value]... [--quiet]
```

- `--ref-frame` 缺省时自动在整段前 90 帧里选与氛围图最相关的一帧，显式给出时按 0 起计。
- 参数名、默认值、场景预设、退出码语义全部与 `vrstudio relight` 相同，直接复用 `resolve_params` 与输入校验函数，不另写一套。
- 编码参数只读 `config.video`（`encoder`/`crf`/`preset`/`pix_fmt`/`audio`/`metadata`），不新增配置键；音频默认从 GT 视频 `copy`。`--crf` 只为像素基线测试覆盖 `video.crf` 而存在。
- `--dump-light` 不提供：诊断图是单帧概念，需要时对参考帧单独跑 `vrstudio relight`。
- 报告字段（决策 64/65 起）：`{gt, atmo, size, frames, fps, kind, started_at, finished_at, cache, timing, ref_frame, ref_matched, params, align, clip, light, seconds}`。`params`/`align`/`clip`/`light` 与图像版同构，新增的是帧数、帧率、参考帧与运行记录（`kind` 为 sample/full，`started_at`/`finished_at` 是本地时区时间戳，`cache` 是缓存状态，`timing` 是准备、小样与整段的分段耗时）。v1 的 `frames_checked`/`min_hold` 已随同位检查删除。报告不是跨仓库契约（沿用决策 48）。

## 6. 代码落点

- `src/vrstudio/relight/`：`align.py` 增加参考帧的 2K 缩略、结构打分与同位判据，相似变换的估计与 warp 未改；`compose.py` 增加 `LightCompose`，把 2K 光场一次放大到原尺寸并折进强度参数，`relight()` 改为它的薄包装、输出逐位不变。相似变换的唯一权威点仍是 `relight/align.py`。
- `src/vrstudio/cli/relight.py`：加 `relight_video` 命令函数，与 `relight` 同文件、共用参数解析与校验；在 `cli/__init__.py` 注册为 `relight-video`。
- 视频 I/O 只用 `media/videoio` 的 `probe`/`FrameReader`/`FrameWriter`（流式逐帧，硬规则 5），不引入第二套帧泵。

## 7. 验收

1. `--strength 0`：引擎在进程内的逐位恒等由图像版测试保证（`test_strength_zero_is_bit_exact_on_full_path`）与光场复用的一致性测试（`test_light_compose_matches_relight`）保证；视频文件层的断言以编码器的固有往返误差为界（同一组解码帧再编码一次的最大偏差，实测 4 级），因为 YUV 转换与 4:2:0 子采样在第二次编码时会重新量化，crf 0 也消不掉。
2. 已知相似变换的合成 GT 视频 + 同场景氛围图：对齐参数恢复在容差内，结构重合度高于闸门，输出帧数与输入一致，音频（若有）保留。
3. 三种失败：2:1 不符 / 尺寸不一致 / 参数越界退出 2；对齐不可信退出 1 且不产出输出视频；参考帧越界退出 2。
4. 报告键集合固定，`--report` 指向不存在的目录时自动创建。
5. 机位移动或运动物体的时间一致性不在本轮验收内，作为已知限制登记在第 3 节。

以上全部已通过，明细见 `docs/test-runs/20261030-relight-video.md`。
