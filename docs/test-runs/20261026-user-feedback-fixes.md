## 2. 问题 3 的完整因果链

1. 抽取 CLI 最后一步才写 `extract.current`（`src/vrstudio/cli/extract.py:190`）；运行期间 API 指向旧版本 `20261021-140105`，该目录没有首尾帧文件（列表核实）。
2. 后端对当前版本目录固定列出首尾两帧（`_patch_step_files`）→ 期间加载的页面显示“缺失”是当时的事实。
3. 完成后不自动刷新的两层原因：完成回调 `if (!running.value) return`，`running` 只在本页点击后置位（`ExtractStep.vue` 旧实现）；且任务轮询 `start()` 只在点击运行/刷新时启动，页面没有数据源。

教训（已进决策条目 §15）：任务驱动的刷新不能依赖“本页发起”的本地标志；`running` 这类状态要从任务列表推导。KeyframeStep / MergeStep 是同一模式，未改，出现同类问题按 §15 处理。

## 5. 问题 2 的排查与实施（2026-10-26 第二次更新）

用户追问"为何 clip.mp4 独立播放流畅、选区/对比页嵌入卡顿"，核实后确认底层差异并实施修复：

- clip.mp4 是 1920×1080 选区片段；选区页放 4096×2048 全景代理（4 倍像素），对比页两路同播且经 WebGL 画布（解码 + 纹理上传 + 着色器，8 倍像素）。
- 独立标签页只是恰好放了最小的那个文件；传输层无差异（同一服务的文件响应）。
- 实施：`web.proxy_max_w` 配置化（决策条目 §17）——默认 4096，本机 `vrstudio.toml` 设 2048；侧车记录 `max_w`，配置变更后旧代理自动失效重建；`_browser_safe` 直连判定跟随；对比页"4K 代理"文案跟随实际宽度。
- 真机验证：8763 运行中改配置，旧 4096 代理 state 即时变 missing；POST 重建后新代理 2048×1024@60、sidecar `max_w=2048`；选区页/对比页标签显示"2048 代理"。
- pytest 370 passed（新增 5 用例）、前端 56 passed。
