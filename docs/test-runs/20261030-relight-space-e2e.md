## 1. 本轮修掉的三个缺陷

**提示词带宽只有真实白带的一半（既有，vrgen）。** `prep/prompt.py::geometry_from_sizes`
用 `band = (w - sw) // 2`（= P = 683），而 `redundant_white` 的 mask 与视频路径都用
`L = w - sw`（= 1366）。后果是模型看到的 mask 白带 1366 列、提示词却说 683，把外侧
683 列真实内容误标成"主内容区"。改为 `band = w - sw`，`column_variables` 不变；
`band_half` 仍是 P。用户提供的提示词里那组 683/8875–9557 是从这份输出抄的，不是写错。

**选参考帧的前置闸门会误杀正常素材（本轮自己加的，已删）。** 原实现在估对齐之前用
「参考帧与氛围图的未对齐带通相关」判 0.15 以下为黑场。拼接后的氛围图带 −9 px 平移时
这个相关从 0.55 掉到 −0.013，实测直接拒掉了本来可用的素材。改为：扫描时用灰度标准差
（`MIN_REFERENCE_STRUCTURE=12`）跳过黑场，配对是否可用只由对齐后的
`correlation_after` 判定，与决策 48「判据只有一条」一致。未对齐相关低于 0.15 时只给警告。

**扫描用的解码器没被关闭（本轮自己写的，已修）。** 选帧循环在第 90 帧 `break`，生成器
停在 `with FrameReader` 内部，那一路 ffmpeg 一直挂着；8K 实测同时存在两个解码器、各占
4.7 GB。三处读视频都改为 `contextlib.closing(open_frames())`。

## 6. 整段结果

`out/20261030-230459_relit.mp4`：8192×4096、378 帧、30fps、H.264 8-bit yuv420p，37 MB；
`[relight] current` 回写为该文件。总耗时 849 秒（含选帧、同位检查与渲染三遍读片）。

对齐（整段唯一一次估计）：内点 53 / 匹配 89、缩放 1.00000、旋转 −0.1206°、
平移 (20.3, 165.0) px@原尺寸；对齐前相关 −0.0129 → 对齐后 **0.5421**，可信。

同位检查：377 帧全部比过，最低 **0.9644**（≥0.94），确认固定机位，无「画面在动」警告。

光照：增益均值 1.433（p05 0.372 / p95 3.728）、可见度均值 0.906（p05 0.263）；
白点矩阵的非对角项最大到 −0.405，说明整体色温被推向暖橙——与氛围图的烛光一致。
增益跨度大（0.37–3.73）是「近亮远暗」的直接体现：烛台附近提亮、背景压暗。

时间稳定性：相邻帧逐像素亮度差的均值，全片最坏值 GT 0.904、成片 **0.662**——成片比 GT 还小，
没有引入闪烁。逐帧整帧均值的最大跳变成片 0.139、GT 0.071（增益放大后 GT 自身运动的变化，
绝对量是 8-bit 均值的小数级）；逐帧均值区间 14.54–15.00，没有漂移。

观感（`E:\VRAIGC\relight_video_test\space_relit_compare.png` 六联：GT 0/189、氛围图、
relit 0/189/377）：梁架、柱身花纹、人物、陈设与前景器皿都在原位；整体转为暖橙烛光调，
前景案几的器皿与烛台明显被点亮，远处灯组形成层层亮点，背景沉入暗部。三帧观感一致。

产物清单（`E:\VRAIGC\relight_video_test`）：`space_first_frame.png`、
`space_atmo_cand2.png` + 报告、`space_relit_cand2.mp4` + 报告、`space_relit_compare.png`。

  约 87 GB 的顺序读，实测受 I/O 限制，扫描 + 同位检查这一段就花了约 30 分钟。
  可行的省法是给这两遍解码加 `-vf scale=2048:-2`，读出量降到 1/16；本轮没改，因为它会
  换掉阈值实测所依据的重采样方式，等下一轮连同阈值一起复测。
