# 视频链路 16-bit 的 WP3/WP4 实施与验收记录（决策 99）

日期：2026-11-13。对应方案 `docs/plan/video-10bit-plan.md` 的 WP3（patch 域）与
WP4（relight 域），代码见 vrstudio 提交 `f448036`（WP3）与 `97491b3`（WP4）。
本文同时记录实施前核实到的编码现状偏差与两项顺带修复。

## 1. 实施前的现状核实

- 所有正式交付件（pad / recompose / seam_center / relight / patch 全链）的**编码档
  已一致**：libx265、yuv420p10le、crf 14、preset slow、BT.709 标签；浏览器代理是
  唯一保留的 H.264 8-bit（crf 22 veryfast，决策 99 允许）。
- 两处偏差：`FfmpegSink` 的 crf/preset 是字面量、不读 `[video]`，导致 `--set
  video.crf` 对 merge/assemble/extract/restore 不生效；`cli/merge.py`、
  `cli/assemble.py`、`patch/extract.py`、`media/ffmpeg.py` 的注释与报告字段仍写
  libx264 / 决策 19。
- 像素内容层：pad / recompose / seam_center 与帧泵是真 16-bit；patch 链与 relight
  的内部计算仍是 8-bit（uint8 帧 `*257` 塞进 10-bit 容器）。

## 2. WP3 patch 域（`f448036`）

- `patch/extract.py`：`read_clip` 改用共享 16-bit `FrameReader`（不再 cv2）；
  写端帧经 `videoio.to_u16`（新增，8→16 显式升位的唯一入口）进 16-bit sink。
- `patch/restore.py`：两处 `FfmpegSink` 走 16-bit；RIFE 的 8-bit PNG 与 cv2 解码
  帧在读入边界显式 `to_u16`；crf/preset 缺省改取 `[video]`。
- `patch/composite.py`：裁剪上限按输出 dtype 取 65535/255（视频路径 uint16，
  patchimg 仍是 8-bit PNG，不改图片位深——计划 §6 明确不做）。
- `cli/merge.py`、`cli/assemble.py`：源与 AI 帧读取全部从 cv2.VideoCapture 改为
  `FrameReader`；`media/videoio.py` 新增 `frame_count`（nb_frames → demux-only
  包计数 → duration 兜底）与 `seek_for_frame`（半帧前置的 `-ss`，保证 accurate
  seek 不被浮点舍入跳帧）；assemble 后段直接 seek 定位，不再逐帧 discard 中段。
- `media/ffmpeg.py`：`FfmpegSink` 缺省从 `[video]` 取，显式参数仍可覆盖；`crf 0`
  补 `lossless=1`（与 FrameWriter 对齐）；四处 libx264 过时注释与报告字段改为
  如实的 libx265。
- dtype 核对：`blend.py`/`projection.py` 的金字塔在 float32、remap 支持 16U；
  `scalefit` 配准固定 8-bit 灰度（ECC/matchTemplate 要求），与帧泵位深无关；
  `framealign` 纯索引运算。

验收：

- `test_patch_flow` / `test_assemble` / `test_merge_contract` /
  `test_extract_contract` / `test_patchimg` / `test_videoio_smoke` /
  `test_restore` 等共 69 条通过；断言未放宽，crf 0 往返仍 maxdiff == 0。
- 16-bit 与帧对齐的人工验证：6 帧、逐帧 16-bit 灰度级 0/1000/…/5000 的源，
  抽区间 2..4 → merge → assemble，输出帧序列 `[0, 912, 1846, 2739, 3675, 4585]`
  恰为前缀帧 0/1 + 段帧 2/3/4 + 后缀帧 5；均值不是 257 的整数倍，证明内容真正
  经过 16-bit 域。产物 pix_fmt 为 yuv420p10le。
- 遗留：`cli/extract.py` 的 ERP 源解码（clip 中间件的输入侧）仍走 cv2 8-bit，
  影响交给平台的输入件精度上限，不影响交付成片；后续如需端到端 16-bit 再立
  工作包。

## 3. WP4 relight 域（`97491b3`）

- `cli/relight.py`：删掉 `_u8_reader`（6 处调用直连 16-bit `FrameReader`）；
  静图输入 `to_u16`；小样 PNG 与诊断六联用新增的 `to_u8_round`（`(v+128)//257`
  就近降位，`to_u16` 的往返逆）降位，注释写明"web 预览 8-bit、交付帧 16-bit"。
- `relight/fields.py`：正向 sRGB→linear 表改 65536 项；反向表网格取 2^20（实测
  65536 格不够：sRGB 暗部斜率 12.92，一个 16-bit 输出级只占 0.077 格，十几个
  暗部码值塌到同一格，strength=0 有 18817 个码值回不去；2^20 后整表往返 0 错值，
  2 MB 常驻、建表 11.7 ms）；量化改四舍五入；`FULL_SCALE = 65535.0` 是唯一满量程
  常量；`SHADOW_PIVOT = 0.01` 本就是 0..1 归一化值，无值可换。
- `relight/compose.py`：`apply` / `soft_clip` / `chroma_lowpass` 全部换
  `FULL_SCALE` 与 uint16、`np.rint` 量化；`clipped_fraction` 门限 64250
  （= 250/255 × 65535，过曝口径与旧实现可比）；行带缓冲仍单份，只随 dtype 变宽。
- `relight/align.py`：`gray8` 是配准域唯一入口（先 `to_u8_round` 降位、再
  INTER_AREA、再取灰度）；决策 64/65 的相似变换缓存不受影响。
- `atmo.py` / `regions.py` / `report.py`：dtype 透传与无量纲 0..1 场的口径注明。

行为等价（8-bit 输入）：

- LUT：65535 = 257×255，65536 表在 257v 处与旧 256 项表逐位一致（测试用逐字
  照抄的旧表断言 array_equal）。
- 配准：灰度逐位一致 + 相似变换矩阵、内点、匹配数、回退分支与冻结的旧实现
  全等（1024 与 3000 两种宽度）。
- strength=0：任意 16-bit 码值（含非 257 倍数）精确往返；CLI 层 PNG 逐像素等于
  GT 的基线保持。
- 8-bit 视频链路：16-bit 上量、16-bit 上比，漂移 444/65535 与一次无损重编码的
  噪声逐帧相等。
- 8-bit 端到端：8K 真实对旧成片 PSNR 50.86 dB；约一半通道值为"旧 = 新 − 1"，
  归因于旧 `chroma_lowpass` 的截断量化（用同一份新光场复算旧量化器复现同一
  偏移）；其余差异集中在近黑区（gain 放大区间）。

实测（8K，本机）：

- 8K 整段 378 帧（20261030-174206_space.mp4 抽帧当氛围图）：旧 429.6 s /
  2269 MiB → 新 374.8 s / 2737 MiB；产物 hevc / yuv420p10le / bt709 / 378 帧；
  与旧成片抽帧对比 PSNR 48.7–50.2 dB。分段：compose 234 s、chroma 139 s、
  decode 55 s、write 71 s。
- 8K 静图对：4.19 s / 1986 MiB → 4.91 s / 2757 MiB（峰值 +39%，三帧 16-bit
  常驻 + 反向表 uint32 索引）。

## 5. 未做与后续入口

- WP4 的遗留观察：`GUIDED_EPS = 300` 疑似历史遗留（引导项实测不生效，滤波
  退化成盒式平滑），改它会改画面，已把实测数据记在代码里，建议单独立项。
- 8K 场估计的 INTER_AREA 在 16U 与 8U 上取整不同（最多 128/65535，约 53% 的
  2K 像素），这是 8-bit 素材在 16-bit 链路上与旧实现不逐位的原因，已写进
  `estimate_fields` 文档；拿到真实 10-bit 素材后应重跑一轮对照。
- WP2 的 `cases/1110-0101` 色带与 PSNR 对照、WP1a 平台输入件接受度仍未做。
- 本文未覆盖浏览器端到端；`docs/plan/relight-region-boolean-plan.md`（决策 100）
  的浏览器验收也待做。
